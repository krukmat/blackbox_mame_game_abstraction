- Minor deviation: `_strip_path_like_segments` (preflight) uses `[^\s,;:]` as path terminators; `_sanitize_execution_output` uses `[^\s\]\)>\"']`. Both are safe but inconsistent. Not blocking — behavior difference only affects edge-case formatting, not policy correctness.

## Parent Cataloging

- Reasoning grade: `High`

## Cataloging Rationale

`T05.3` remains `High` because it implements the clean-room public-output policy directly in code. A mistake here can leak ROM locations, private evidence paths, or local machine paths into public metadata even if the written policy is correct.

## Subtasks

### T05.3.1 Command Sanitization

- Objective: implement element-wise sanitization for `command[*]`.
- Scope:
  - private evidence path replacement to `private://...`
  - ROM-path sanitization
  - absolute local path sanitization
  - explicit allowlist handling for repo-safe relative references
- Out of scope:
  - `preflight` and `execution` text sanitization
- Dependencies:
  - `T05.2`
- Reasoning grade: `Medium`
- Effort grade: `Low`
- Recommended model: `gpt-5.4-mini`
- Acceptance criteria:
  - `command[*]` preserves only allowed public forms
  - blocked path forms do not remain verbatim

### T05.3.2 Preflight Message Sanitization

- Objective: sanitize `preflight.issues[*].message` into path-free operational text.
- Scope:
  - remove or rewrite private evidence paths
  - remove or rewrite ROM paths
  - remove or rewrite absolute local machine paths
  - remove or rewrite non-approved workspace-relative paths
- Out of scope:
  - `execution.stdout` and `execution.stderr`
- Dependencies:
  - `T05.2`
  - `T05.3.1`
- Reasoning grade: `Medium`
- Effort grade: `Low`
- Recommended model: `gpt-5.4-mini`
- Acceptance criteria:
  - preflight messages preserve operational meaning without exposing path-bearing content

### T05.3.3 Execution Output Sanitization

- Objective: sanitize `execution.stdout` and `execution.stderr` into path-free public-safe output.
- Scope:
  - path-bearing process output
  - private evidence, ROM, absolute local, frame, crop, and non-approved workspace path content
- Out of scope:
  - command argument sanitization
- Dependencies:
  - `T05.2`
  - `T05.3.1`
- Reasoning grade: `Medium`
- Effort grade: `Medium`
- Recommended model: `gpt-5.4`
- Acceptance criteria:
  - stdout/stderr retain only path-free operational meaning

### T05.3.4 Writer and Guardrail Enforcement

- Objective: align `metadata_writer.py` and `guardrails.py` with the finalized policy so unsanitized payloads are rejected.
- Scope:
  - last-gate rejection of forbidden public path forms
  - allowlist-aware enforcement for repo-safe relative references where relevant
- Out of scope:
  - broad non-runtime schema redesign
- Dependencies:
  - `T05.3.1`
  - `T05.3.2`
  - `T05.3.3`
- Reasoning grade: `Medium`
- Effort grade: `Low`
- Recommended model: `gpt-5.4-mini`
- Acceptance criteria:
  - unsanitized public payloads fail at the writer/guardrail layer

### T05.3.5 Implementation Consistency Review

- Objective: verify that command sanitization, message sanitization, output sanitization, and writer enforcement all implement the same policy.
- Scope:
  - consistency across `cli.py`, `guardrails.py`, and `metadata_writer.py`
- Out of scope:
  - the broader regression suite in `T05.4`
- Dependencies:
  - `T05.3.1`
  - `T05.3.2`
  - `T05.3.3`
  - `T05.3.4`
- Reasoning grade: `High`
- Effort grade: `Low`
- Recommended model: `gpt-5.4`
- Acceptance criteria:
  - no layer reintroduces a weaker interpretation of the redaction policy
  - implementation is ready for regression testing in `T05.4`
