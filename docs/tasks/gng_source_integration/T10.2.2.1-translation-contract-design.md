## Purpose

Define the exact mapping rules from `FrameDiffStat` to `TraceEntry` fields before any code is written. This contract is the specification that T10.2.2.2 and T10.2.2.3 must implement. Ambiguities resolved here prevent naming-drift bugs later.

## Reference Reasoning

`Medium`

Reasoning basis:

- velocity thresholds and state assignment rules are design decisions, not derivable from existing code
- the event inference table must be decided before implementation — changing it after T10.2.2.3 requires re-testing all state transition cases
- the input plan correlation strategy (how fire/jump events are detected when no motion is visible) must be explicit

## Scope

Define and document the following mappings in `## Contract` section of this file:

1. **Velocity computation**: how `velocity_x` and `velocity_y` are derived from `center_x`/`center_y` delta between consecutive `FrameDiffStat` records
2. **State assignment rules**: velocity threshold table mapping `(vx, vy)` ranges to state enum values (`idle`, `walking_left`, `walking_right`, `grounded`, `airborne`, `ascending`, `descending`)
3. **Event inference table**: state transition pairs → event list (e.g. `grounded → airborne` = `[jump_start]`, `airborne(vy<0) → airborne(vy>0)` = `[jump_peak]`, `airborne → grounded` = `[land]`)
4. **Input plan correlation**: how `action` in `FrameInput` is used to inject `fire` and `jump_start` events on frames where visual motion is absent or ambiguous
5. **Entity ID assignment**: which entity_type to assign based on motion region size relative to frame dimensions
6. **Spawn/die detection**: which frame conditions trigger `spawn` and `die` events

## Contract

### Rule 1 — Velocity Computation

`velocity_x` and `velocity_y` for a frame interval `[F, F+1]` are computed
from the **normalized center displacement** of the primary `MotionBox`.

Let `W` = frame width (integer), `H` = frame height (integer).

```
dx = current.center_x  − previous.center_x       # raw pixel delta
dy = current.center_y  − previous.center_y

velocity_x = dx / W    # normalized: range (-1.0, +1.0)
velocity_y = dy / H    # normalized: range (-1.0, +1.0)
```

**Degenerate cases:**

| Condition | Result |
|-----------|--------|
| `changed_regions == []` on either frame | `velocity_x = 0.0`, `velocity_y = 0.0` |
| Only one frame has a region; the other does not | treat missing region center as the existing region center → both deltas = 0.0 |
| Multiple regions present (future implementation) | use the region with the largest area (width × height) as the primary region |

Frame dimensions are taken from `FrameManifest.frame_width` and
`FrameManifest.frame_height`.  These are the same values used during pixel
loading and are never written to public output (ADR-006 Rule 1).

---

### Rule 2 — State Assignment Table

States are assigned by applying the following table in order.  The first
matching row wins.  All velocity values are normalized (Rule 1 output).

`VX_STILL` = 0.005 (ratio: motion smaller than 0.5 % of frame width is idle)
`VY_STILL` = 0.005 (ratio: motion smaller than 0.5 % of frame height is still)
`VY_NEG`   = −VY_STILL  (strictly negative after deadband)
`VY_POS`   = +VY_STILL  (strictly positive after deadband)

| Priority | Condition | Assigned state |
|----------|-----------|----------------|
| 1 | `entity_type == "projectile"` AND `velocity_x != 0.0` | `in_flight` |
| 2 | `entity_type == "projectile"` AND `velocity_x == 0.0` | `despawned` |
| 3 | `abs(velocity_y) > VY_STILL` AND `velocity_y < 0` | `ascending` |
| 4 | `abs(velocity_y) > VY_STILL` AND `velocity_y > 0` | `descending` |
| 5 | `abs(velocity_y) <= VY_STILL` AND `abs(velocity_x) <= VX_STILL` | `idle` |
| 6 | `abs(velocity_y) <= VY_STILL` AND `velocity_x < −VX_STILL` | `walking_left` |
| 7 | `abs(velocity_y) <= VY_STILL` AND `velocity_x > +VX_STILL` | `walking_right` |
| 8 | `abs(velocity_y) > VY_STILL` (neither ascending nor descending) | `airborne` |
| 9 | fallback | `grounded` |

**Mapping to entity_event_trace state.enum (T09.2):**
All nine output strings (`in_flight`, `despawned`, `ascending`, `descending`,
`idle`, `walking_left`, `walking_right`, `airborne`, `grounded`) are members of
the canonical `state.enum`.  No additional string may be emitted.

---

### Rule 3 — Event Inference Table

Events are derived from `(prev_state, curr_state)` pairs evaluated after state
assignment (Rule 2).  Multiple events may be emitted on the same frame.

| `prev_state` | `curr_state` | Emitted events |
|--------------|--------------|----------------|
| `idle` or `walking_left` or `walking_right` or `grounded` | `ascending` | `[jump_start]` |
| `ascending` | `descending` | `[jump_peak]` |
| `ascending` or `descending` or `airborne` | `grounded` or `idle` | `[land]` |
| `grounded` or `idle` | `airborne` or `descending` | `[fall]` |
| `idle` | `walking_left` or `walking_right` | `[movement_start]` |
| `walking_left` or `walking_right` | `idle` | `[movement_stop]` |
| `walking_left` | `walking_right` | `[movement_stop, movement_start]` |
| `walking_right` | `walking_left` | `[movement_stop, movement_start]` |
| `in_flight` | `despawned` | `[despawn]` |
| any | any (same as above — no transition) | `[]` |

**Ordering rule**: when multiple events are emitted, follow the order in which
they appear left-to-right in the table row above.

**First-frame bootstrap**: on frame 0 there is no previous frame, so `prev_state`
is set to the same value as `curr_state`.  No transition events are inferred on
frame 0 (only Rule 4 injection and Rule 6 spawn detection apply).

All emitted event strings (`jump_start`, `jump_peak`, `land`, `fall`,
`movement_start`, `movement_stop`, `despawn`) are members of the canonical
`events.enum` (T09.2).

---

### Rule 4 — Input Plan Correlation

`FrameInput.action` (from `input_planner.py`) is consulted on every frame to
inject events that visual motion alone cannot confirm.  These injections
supplement — they do not replace — the event inference in Rule 3.

| `FrameInput.action` | Injection condition | Injected event |
|---------------------|---------------------|----------------|
| `"fire"` | Always inject on the frame where `action == "fire"` | `fire` |
| `"jump"` | Inject only if Rule 2 state is NOT already `ascending` (prevents double-emit when motion is visible) | `jump_start` |

**Ordering**: injected events are appended **after** the Rule 3 event list for
the same frame, before deduplication.

**Deduplication**: if the same event string would appear twice (e.g. Rule 3
already inferred `jump_start` and Rule 4 also injects it), keep only one
occurrence and preserve its position from Rule 3.

**No input plan available**: if no `FrameInput` record exists for a given frame
(e.g. the plan is shorter than the capture), skip Rule 4 for that frame — do
not error.

The `fire` event string is a member of `events.enum` (T09.2).
`jump_start` is already listed in Rule 3; re-listed here for completeness.

---

### Rule 5 — Entity ID Assignment from MotionBox Size Ratio

Entity type is inferred from the **area ratio** of the `MotionBox` relative to
the full frame area.

Let `box_ratio = (region.width × region.height) / (W × H)`.

| `box_ratio` range | Assigned `entity_type` | Assigned `entity_id` pattern |
|-------------------|------------------------|-------------------------------|
| `≥ 0.04` | `player` | `"player"` |
| `[0.005, 0.04)` | `enemy_a` | `"enemy_a_<frame>"` |
| `[0.0005, 0.005)` | `projectile` | `"projectile_<frame>"` |
| `< 0.0005` | `hazard` | `"hazard_<frame>"` |

`<frame>` is the `start_frame` value from `FrameDiffStat`, used as a
unique suffix when multiple entities of the same type could appear.

**Tie-breaking** (future multi-region case): if two regions fall into the same
bucket, the one with the smaller `y` value (higher on screen) is assigned the
lower-numbered suffix.

**Override rule**: if `FrameInput.action == "fire"` on the current frame, a
`projectile` entity record is always emitted regardless of `box_ratio`, because
a newly spawned projectile may not yet show a large motion delta.

All `entity_type` strings (`player`, `enemy_a`, `projectile`, `hazard`) are
members of `entity_event_trace.entity_type.enum` (T09.2).

---

### Rule 6 — Spawn and Die Detection

**Spawn detection** (`spawn` event):

A `spawn` event is emitted on frame F for entity `E` when:

1. Frame F contains a `MotionBox` in the size bucket matching `E`'s `entity_type`
   (Rule 5), AND
2. Frame F−1 contains **no** `MotionBox` in that same bucket (entity was absent
   in the previous diff).

On frame 0 (no F−1 available), `spawn` is emitted unconditionally for every
entity detected in that frame.

**Die detection** (`die` event):

A `die` event is emitted on frame F for entity `E` when:

1. Frame F contains a `MotionBox` matching `E`'s bucket, AND
2. Frame F+1 contains **no** `MotionBox` in that bucket (entity disappears next
   frame), AND
3. The entity's `state` on frame F is NOT `despawned` (a projectile despawn is
   handled by Rule 3, not Rule 6).

On the final captured frame (no F+1 available), no `die` event is inferred
(absence of future frames is not evidence of death).

**`despawn` vs `die`**:

- `die` is a behavioral event (health reached zero, enemy defeated).
- `despawn` is a structural event (entity removed from scene, emitted by Rule 3
  when `in_flight → despawned` for projectiles).
- Both are members of `events.enum` (T09.2) and may co-occur on the same frame
  for a defeated enemy that also leaves the scene.
