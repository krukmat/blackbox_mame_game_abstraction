# T10.9.2 — Red Arremer Signature Calibration

## Status

🔲 Planned — awaiting parent-task approval.

## Parent Task

[T10.9 — Boss and Devil Tracking](./T10.9-boss-and-devil-tracking.md)

## Objective

Calibrate an `EnemySignature` for the Red Arremer (`enemy_c`) using the ADR-019 picker pattern, and append it to `specs/calibration/gng_enemy_signatures.yaml`. The Red Arremer is a mid-stage flying enemy with high vertical motion variance; its signature must accommodate both perched and in-flight poses.

## Scope

- Extend `apps/mame-harness/enemy_signature_picker.py` (created in T10.8.1) — or fork into `apps/mame-harness/boss_signature_picker.py` — to surface candidate Red Arremer clusters. The Arremer's larger size and high `max_frame_jump_px` require relaxed clustering windows relative to T10.8's zombi/crow.
- Run the picker over `run_t10_4_01` and any complementary captures.
- Operator validates ≥ 3 Red Arremer candidate clusters covering both perched (low `velocity_y` variance) and in-flight (high variance) frames.
- Extend `apps/mame-harness/enemy_signature_calibrator.py` to compute Arremer-specific bounds (including a high `max_frame_jump_px`).
- Append the `enemy_c` section to `specs/calibration/gng_enemy_signatures.yaml`.
- Regression tests:
  - Picker excludes player-claimed regions and zombi/crow-claimed regions (signatures already in the YAML take precedence).
  - Calibrator computes a `max_frame_jump_px` ≥ the 95th percentile of accepted in-flight |Δcenter|.

## Out of Scope

- Cyclops calibration (T10.9.3).
- Behavior modelling (swoop arc, projectile timing) — captured by trace continuity, not by signature.
- Modifying the `EntityTracker` algorithm.

## Dependencies

- ✅ T10.9.1 — scroll-aware pipeline enables Arremer detection on screens beyond the first.
- ✅ T10.8.1 — picker infrastructure exists.
- ✅ T10.8.2 — `EntityTracker` consumes additional signatures without code changes (only YAML).

## Acceptance Criteria

1. Picker surfaces candidate Red Arremer clusters with frame ranges; stdout contains no PNG paths.
2. Operator has accepted ≥ 3 clusters covering both perched and in-flight motion.
3. `specs/calibration/gng_enemy_signatures.yaml` contains an `enemy_c` section with:
   - `height_min/max`, `center_y_min/max`, `aspect_ratio_min/max`.
   - `max_frame_jump_px` ≥ 95th percentile of accepted in-flight |Δcenter|.
   - `gap_tolerance_frames` ≥ 5.
   - `sample_count`, `calibration_source`, `calibration_method`.
4. YAML passes `ensure_no_private_paths`.
5. Regression test verifies picker excludes regions claimed by player/zombi/crow signatures already in the YAML.
