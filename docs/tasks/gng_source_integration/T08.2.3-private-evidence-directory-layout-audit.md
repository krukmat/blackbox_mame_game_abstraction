## Gaps Discovered (risk for T09)

### Gap 1 — `states/` not pre-created

`capture_manager.py:34` creates `frames/`, `video/`, `logs/`, `metadata/` only. The `states/` directory is passed to MAME via `-state_directory` but never pre-created. MAME does not create it unless it writes save states. For observation-only runs this is correct behavior. The acceptance criterion was overstated.

**Severity:** Low. Does not block capture.

### Gap 2 — AVI written inside `frames/`, not `video/`

MAME resolves `-aviwrite` relative to `-snapshot_directory` when the path is relative. Result:

```
frames/evidence/private/run_ed0cb0ac19a4/video/capture.avi   ← wrong location
gngb/0000.png
video/   ← empty
```

**Fix required before T09:** resolve `-aviwrite` path to absolute before passing to MAME (`Path.resolve()` in `build_mame_command`).

### Gap 3 — Only 1 PNG captured in `frames/`

`-snapshot_directory` only stores manual screenshots (F12 or Lua `snapshot` command), not automatic per-frame capture. `gngb/0000.png` is the initial snapshot only. Frame-by-frame capture requires either a working Lua script or correct `-aviwrite` routing.

**Fix required before T09:** resolve Gap 2 (correct AVI path) and fix Lua `emu.framecount()` API (documented in T08.2.2).
