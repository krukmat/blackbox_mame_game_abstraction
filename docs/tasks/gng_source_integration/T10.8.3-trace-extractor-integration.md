# T10.8.3 — trace_extractor Integration with EntityTracker

## Status

🔲 Planned — awaiting parent-task approval.

## Parent Task

[T10.8 — Enemy Tracking Continuity](./T10.8-enemy-tracking-continuity.md)

## Objective

Wire `EntityTracker` (from T10.8.2) and the calibrated `EnemySignature` bounds (from T10.8.1) into `packages/vision/trace_extractor.py` so that non-player `entity_id` values are persistent across frames, and per-entity `spawn` and `die` events are emitted from the tracker's lifecycle output rather than from per-frame heuristics.

## Scope

- Add a loader for `specs/calibration/gng_enemy_signatures.yaml` that returns a list of `EntitySignature` instances.
- In `extract_trace`:
  - Instantiate a single `EntityTracker` configured with `ArthurSignature()` and the loaded enemy signatures.
  - Replace the manual player + `_regions_except_claimed` + `_entity_type_from_box` scan with `tracker.step(regions, frame)`.
  - Use `TrackedEntity.entity_id` directly as the trace `entity_id`; remove `_entity_id_from_type` for tracked entities.
  - Retain `_entity_type_from_box` only as a fallback for regions unclaimed by any signature (residual `hazard` classification).
  - Emit `spawn` events for entities in `StepResult.spawned`.
  - Emit `die` events retroactively on the last entry of entities in `StepResult.died`, mirroring the existing player-gap pattern in `trace_extractor.py:308-326`.
- Preserve all existing per-entity bookkeeping (`prev_state_by_entity`, `prev_region_by_entity`, `ground_streak_by_entity`) — keys remain the new persistent `entity_id` values.
- Preserve `legacy_aggregate_compat` path for harness tests that pass aggregate blobs.
- `player_gap_tolerance` from `GNGVisionConfig` remains the source of truth for player-specific gap; enemy gap comes from per-signature `gap_tolerance_frames`.

## Out of Scope

- Modifying the trace JSON schema (`trace.schema.json`).
- Adding new state or event enums beyond what is already in T09.2.
- Changes to `frame_differ.py` or `gng_vision_config.py` semantics.
- Regenerating `gng_trace.json` — that happens in T10.8.5 after tests pass.
- Updates to `physics_calibrator.py` or `episode_extractor.py`.

## Dependencies

- ✅ T10.8.1 — `gng_enemy_signatures.yaml` must exist and be calibrated.
- ✅ T10.8.2 — `EntityTracker` must exist and be tested.

## Acceptance Criteria

1. `extract_trace` instantiates one `EntityTracker` per call with player + enemy signatures loaded from YAML.
2. Non-player `entity_id` values are of the form `{entity_type}_{spawn_frame}_{spawn_index}` and remain stable across all frames in which the entity is detected.
3. `spawn` events are emitted only on first appearance of each `entity_id` (not on every frame).
4. `die` events are emitted on the last real-detection entry of each entity that closes via gap-tolerance exceedance.
5. `legacy_aggregate_compat=True` callers retain identical output to pre-T10.8 behavior (legacy harness contract preserved).
6. The fallback path for regions unclaimed by any signature (`hazard`) preserves the existing `_entity_type_from_box` classification.
7. Regression tests in `packages/vision/tests/test_trace_extractor_enemies.py`:
   - Single zombi over 20 frames produces one `entity_id`, one `spawn`, one `die`.
   - Two zombis spawning in different frames produce two distinct `entity_id` values.
   - Crow flying with vertical oscillation maintains continuity across `velocity_y` sign changes.
   - Enemy disappearing for 2 frames inside gap tolerance is bridged; same `entity_id` resumes.
   - Enemy disappearing for `gap_tolerance + 1` frames triggers `die` on its last-seen entry.
8. Existing tests in `packages/vision/tests/test_trace_extractor_multi.py` and `test_gap_tolerance.py` pass unchanged.
9. `pytest packages/vision/tests/` passes in full.

## Files Affected

### New

- `packages/vision/tests/test_trace_extractor_enemies.py`

### Modified

- `packages/vision/trace_extractor.py` — main integration.
- `packages/vision/gng_vision_config.py` — add path to enemy signatures YAML if not loaded externally (TBD during implementation; prefer loading inside `extract_trace` to keep config dataclass simple).

## Risks

- **R1 — Legacy aggregate path breakage**: harness tests with single-blob inputs must not regress. Mitigation: explicit branch on `legacy_aggregate_compat` before delegating to `EntityTracker`.
- **R2 — Signature-claim ambiguity**: a region matching both player and enemy bounds (after T10.7.B fix this should not occur, but) — `EntityTracker` greedy ordering by `spawn_frame` ascending naturally favors longer-lived tracks (player), so behavior is deterministic.
