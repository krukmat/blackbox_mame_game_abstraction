# T05.2.1 - Sensitive Surface Inventory Consolidation

## Status

Completed

## Purpose

Normalize the `T05.1` audit into a single inventory of sensitive value classes and affected public fields so later policy work can operate from one shared reference.

## Normalized Sensitive Value Classes

### S1. Private evidence path

Definition:

- any path under `evidence/private/...`

Examples:

- `evidence/private/run_demo/frames/frame_0001.png`
- `evidence/private/run_demo/video/capture.avi`
- `evidence/private/run_demo/logs`

### S2. Frame path

Definition:

- any path that directly references frame artifacts or frame directories

Examples:

- `/frames/frame_0001.png`
- `evidence/private/run_demo/frames`

### S3. Crop path

Definition:

- any path that directly references crops or crop directories

Examples:

- `/crops/candidate_001.png`
- `datasets/derived/crops/candidate_001.png`

### S4. Direct ROM path

Definition:

- any filesystem path or path-shaped string that directly reveals ROM storage or a ROM zip location

Examples:

- `/roms/gng.zip`
- `/Users/me/local/roms/gng.zip`
- `../gng.zip`

### S5. Absolute local machine path

Definition:

- any absolute path that reveals machine-local filesystem structure

Examples:

- `/Users/name/project/...`
- `/tmp/gng-run/...`
- `C:\\Users\\name\\project\\...`

### S6. Non-private workspace path in public runtime payload

Definition:

- any repo-relative or workspace-relative path that is not itself private evidence, but still appears inside public runtime payloads and may reveal local execution details

Examples:

- `scripts/mame_autoboot.lua`
- other repo-relative command arguments or resolved helper paths

Note:

- this class is not automatically forbidden; it must be categorized by policy as allowed, replaced, or blocked per field and usage.

### S7. Path-bearing process output

Definition:

- human-readable process output that may contain embedded local paths

Examples:

- `execution.stdout`
- `execution.stderr`

### S8. Path-bearing validation message

Definition:

- structured validation messages that may embed machine-local or ROM-local paths

Examples:

- `preflight.issues[*].message`

## Normalized Affected Public Fields

### F1. `command[*]`

Why it matters:

- contains raw command arguments
- may expose private evidence paths, ROM paths, absolute paths, or repo-relative execution details

### F2. `preflight.issues[*].message`

Why it matters:

- currently human-readable and may embed resolved filesystem paths for binaries or ROMs

### F3. `execution.stdout`

Why it matters:

- may carry unsanitized process output emitted by MAME or a wrapper executable

### F4. `execution.stderr`

Why it matters:

- may carry unsanitized error output with paths, filenames, or local machine details

### F5. Any future string field written by `handle_run`

Why it matters:

- future public metadata changes must inherit the same policy instead of bypassing it accidentally

### F6. Any public metadata payload written through `write_public_metadata`

Why it matters:

- the writer is the last public-output gate and must be covered by the same inventory

## Consolidation Outcome

The inventory confirms that `T05.2.2` and `T05.2.3` must classify values by sensitive class first, not by source module. The same class can appear in multiple public fields, and the same field can carry multiple sensitive classes.

This means the unified policy must be expressed as:

- sensitive value class
- affected public field
- allowed, replaced, or blocked action

instead of as isolated per-function exceptions.
