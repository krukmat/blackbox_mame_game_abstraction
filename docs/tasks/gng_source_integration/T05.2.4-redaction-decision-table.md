# T05.2.4 - Redaction Decision Table

## Status

Completed

## Purpose

Define one public-handling action per sensitive value class and affected public field: `allow`, `replace`, or `block`.

## Action Definitions

- `allow`: the value may remain as-is in public metadata
- `replace`: the original value may not remain verbatim and must be transformed into an allowed public form
- `block`: the value must not remain in public metadata and no direct public representation is allowed in that field

## Decision Table

| Sensitive class | `command[*]` | `preflight.issues[*].message` | `execution.stdout` | `execution.stderr` | Future public string fields | Notes |
|---|---|---|---|---|---|---|
| `S1 Private evidence path` | `replace` | `replace` | `replace` | `replace` | `replace` | Replace with opaque `private://...` handles or path-free wording. |
| `S2 Frame path` | `replace` | `replace` | `replace` | `replace` | `replace` | Frame references must never remain verbatim in public output. |
| `S3 Crop path` | `block` | `replace` | `replace` | `replace` | `replace` | Crop paths should not appear in command payloads; in messages/output they must be removed or rewritten path-free. |
| `S4 Direct ROM path` | `replace` | `replace` | `replace` | `replace` | `replace` | ROM-local meaning may remain only after removing filesystem disclosure. |
| `S5 Absolute local machine path` | `replace` | `replace` | `replace` | `replace` | `replace` | Preserve operational meaning only through sanitized or abstract wording. |
| `S6 Non-private workspace path in public runtime payload` | `allow` or `replace` | `replace` | `replace` | `replace` | `allow` or `replace` | Allowed only when explicitly repo-safe under `T05.2.2`; otherwise replace. |
| `S7 Path-bearing process output` | N/A | N/A | `replace` | `replace` | N/A | Output text may survive only after path sanitization. |
| `S8 Path-bearing validation message` | N/A | `replace` | N/A | N/A | N/A | Validation detail may survive only after path sanitization. |

## Field-Level Interpretation

### `command[*]`

- may keep:
  - abstract arguments
  - non-path scalars
  - repo-safe public relative references
  - opaque `private://...` handles
- must not keep verbatim:
  - raw private evidence paths
  - ROM paths
  - absolute local machine paths
  - non-approved workspace paths

### `preflight.issues[*].message`

- may keep:
  - path-free operational explanations
  - opaque handles if needed
- must not keep verbatim:
  - any private evidence path
  - any ROM path
  - any absolute local path
  - any non-approved workspace path

### `execution.stdout` and `execution.stderr`

- may keep:
  - sanitized, path-free output
  - abstract operational meaning
- must not keep verbatim:
  - private evidence paths
  - ROM paths
  - absolute local paths
  - non-approved workspace paths
  - frame/crop references

### Future public string fields

- default rule:
  - if the field can carry a sensitive class, it must follow the same class-to-action mapping above
- no new public string field may bypass this table

## Additional Decision Rules

### R1. Replace beats raw retention

If a value belongs to a blocked sensitive class but still has public operational meaning, the value must be `replace`, not `allow`.

### R2. Opaque handle replacement is preferred for private evidence references

When a value points to private evidence and traceability matters, replace it with a `private://...` form rather than dropping all reference context.

### R3. Path-free wording is preferred for messages and process output

For `preflight.issues[*].message`, `execution.stdout`, and `execution.stderr`, replacement should preserve meaning without preserving any machine-local or ROM-local path string.

### R4. Repo-safe references are opt-in, not default

Workspace-relative strings are not presumed safe. They are only `allow` when they match the repo-safe form defined in `T05.2.2`.

## Implementation Handoff Notes For `T05.3`

- sanitize `command[*]` element-wise
- sanitize `preflight.issues[*].message` message-wise
- sanitize `execution.stdout` and `execution.stderr` as free-form text fields
- treat unknown future public string fields as needing the same sensitive-class scan before writing
