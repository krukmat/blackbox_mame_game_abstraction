## Draft Schema

> All values are in abstract game units unless explicitly marked. No pixel coordinates, no ROM addresses, no copyrighted names.
> Vocabularies defined here are canonical — T10 (extraction) and T11 (RN prototype) must use identical string values to avoid silent mismatches (ADR-008 Known Gap).

### 1. `locomotion`

Extends `trace.schema.json` base contract. Player-controlled horizontal movement.

```yaml
locomotion:
  # Inherits from TraceEntry (required by base contract)
  frame:             { type: integer, minimum: 0, required: true }
  entity_id:         { type: string, required: true }
  entity_type:       { type: string, enum: [player], required: true }
  x:                 { type: number, required: true, notes: "abstract units, not pixels" }
  y:                 { type: number, required: true, notes: "abstract units, not pixels" }
  velocity_x:        { type: number, required: true, notes: "constant while input held; 0.0 on release" }
  velocity_y:        { type: number, required: true, notes: "0.0 for grounded locomotion" }

  state:
    type: string
    required: true
    enum:
      - idle             # no input held, velocity_x == 0
      - walking_left     # left input held, velocity_x < 0
      - walking_right    # right input held, velocity_x > 0

  events:
    type: array
    items:
      type: string
      enum:
        - movement_start   # transition from idle to walking
        - movement_stop    # transition from walking to idle
    required: true
    notes: "empty list [] when no transition occurs on this frame"

  score_delta:  { type: integer, required: false, default: 0 }
```

**Constraints:**
- `velocity_x` must be non-zero iff state is `walking_left` or `walking_right`.
- No acceleration or inertia — velocity_x is discrete (constant or zero).
- `entity_type` is always `player` for locomotion records.

### 2. `jump_arc`

Deterministic vertical trajectory. Jump cannot be cancelled mid-air.

```yaml
jump_arc:
  # Inherits from TraceEntry
  frame:             { type: integer, minimum: 0, required: true }
  entity_id:         { type: string, required: true }
  entity_type:       { type: string, enum: [player], required: true }
  x:                 { type: number, required: true }
  y:                 { type: number, required: true }
  velocity_x:        { type: number, required: true }
  velocity_y:
    type: number
    required: true
    notes: "negative = ascending (upward), positive = descending (downward), 0.0 = peak or grounded"

  state:
    type: string
    required: true
    enum:
      - grounded     # on a surface, velocity_y == 0
      - ascending    # airborne, velocity_y < 0
      - descending   # airborne, velocity_y > 0

  events:
    type: array
    required: true
    items:
      type: string
      enum:
        - jump_start   # first airborne frame; velocity_y transitions to negative
        - jump_peak    # frame where velocity_y crosses zero (ascending → descending)
        - land         # first grounded frame after airborne; velocity_y set to 0
    notes: "at most one of [jump_start, jump_peak, land] per frame; [] on interior frames"

  score_delta: { type: integer, required: false, default: 0 }
```

**Constraints:**
- `state: grounded` → `velocity_y == 0.0`.
- `state: ascending` → `velocity_y < 0`.
- `state: descending` → `velocity_y > 0`.
- Jump trajectory is fully deterministic: no mid-air cancellation, no variable height.
- Timing calibration (initial velocity, gravity constant) deferred to T10 from real gameplay capture.

### 3. `projectile`

Fixed-velocity projectile with spawn delay. Maximum one active projectile per player at a time.

```yaml
projectile:
  # Inherits from TraceEntry
  frame:             { type: integer, minimum: 0, required: true }
  entity_id:         { type: string, required: true, notes: "e.g. 'projectile_0' — no copyrighted name" }
  entity_type:       { type: string, enum: [projectile], required: true }
  x:                 { type: number, required: true }
  y:                 { type: number, required: true }
  velocity_x:
    type: number
    required: true
    notes: "constant; sign matches player facing direction; calibrated in T10"
  velocity_y:        { type: number, required: true, default: 0.0, notes: "horizontal projectile; 0.0 unless arc variant" }

  state:
    type: string
    required: true
    enum:
      - in_flight    # active, traveling
      - despawned    # removed from scene (terminal state, last frame only)

  events:
    type: array
    required: true
    items:
      type: string
      enum:
        - fire          # projectile spawned (first frame of existence)
        - hit_enemy     # collided with enemy entity
        - hit_wall      # collided with level boundary or obstacle
        - despawn       # removed — always co-occurs with hit_enemy, hit_wall, or off-screen exit
    notes: "fire appears on spawn frame only; despawn co-occurs with a collision event or off-screen"

  # Mechanic-specific extension (not in base TraceEntry)
  spawn_delay_frames:
    type: integer
    minimum: 0
    required: false
    notes: "frames elapsed between fire input and this projectile's first frame; populated on the fire event frame only"

  score_delta: { type: integer, required: false, default: 0 }
```

**Constraints:**
- `entity_id` must not contain the in-game weapon name (copyright risk). Use `projectile_0`, `projectile_1`, etc.
- `spawn_delay_frames` is populated only on the frame where `fire` event appears.
- At most one `projectile` entity with `state: in_flight` per player at any frame.

### 4. `gravity_collision`

Per-frame gravity application and ground collision detection.

```yaml
gravity_collision:
  # Inherits from TraceEntry
  frame:             { type: integer, minimum: 0, required: true }
  entity_id:         { type: string, required: true }
  entity_type:       { type: string, required: true }
  x:                 { type: number, required: true }
  y:                 { type: number, required: true }
  velocity_x:        { type: number, required: true }
  velocity_y:
    type: number
    required: true
    notes: "incremented by gravity_units_per_frame each airborne frame; reset to 0 on land"

  state:
    type: string
    required: true
    enum:
      - grounded   # entity resting on a surface
      - airborne   # entity in free fall or jump arc

  events:
    type: array
    required: true
    items:
      type: string
      enum:
        - land   # airborne → grounded transition; velocity_y set to 0
        - fall   # grounded → airborne transition (walked off edge or knocked off)
    notes: "[] on frames with no state transition"

  # Mechanic-specific extension
  gravity_units_per_frame:
    type: number
    required: false
    notes: "positive constant added to velocity_y each airborne frame; calibrated in T10 from real capture; do not set from ROM values"

  score_delta: { type: integer, required: false, default: 0 }
```

**Constraints:**
- `gravity_units_per_frame` is a behavioral constant, not a ROM address or pixel count.
- `state: grounded` → `velocity_y == 0.0`.
- `land` and `fall` events are mutually exclusive on any single frame.

### 5. `entity_event_trace`

Per-frame lifecycle event log for any entity type. Full extension of `trace.schema.json` base contract with canonical state and event vocabularies for T10/T11 alignment.

```yaml
entity_event_trace:
  # All fields from TraceEntry are required
  frame:             { type: integer, minimum: 0, required: true }
  entity_id:         { type: string, required: true, notes: "use role labels: player, enemy_a, enemy_b, boss_a, projectile_0, …" }
  entity_type:
    type: string
    required: true
    enum:
      - player
      - enemy_a      # generic enemy archetype A (ground-based)
      - enemy_b      # generic enemy archetype B (airborne or ranged)
      - boss_a       # stage boss archetype
      - projectile   # player-fired projectile
      - hazard       # environmental hazard (pit, spike, etc.)
    notes: "no copyrighted names; archetypes only"
  x:                 { type: number, required: true }
  y:                 { type: number, required: true }
  velocity_x:        { type: number, required: true }
  velocity_y:        { type: number, required: true }

  state:
    type: string
    required: true
    enum:
      # Shared states
      - idle
      - walking_left
      - walking_right
      - grounded
      - airborne
      - ascending
      - descending
      - in_flight
      - hit           # entity in damage/knockback state
      - dead          # entity eliminated, pending removal
      - despawned     # entity removed from scene (terminal)
    notes: "each entity_type uses a subset; unknown states must not be emitted — add to vocabulary first"

  events:
    type: array
    required: true
    items:
      type: string
      enum:
        # Lifecycle
        - spawn         # entity appears on screen
        - die           # entity health reaches zero
        - despawn       # entity removed (after die or off-screen)
        # Combat
        - hit           # entity takes damage
        - hit_enemy     # entity's projectile or body hits an enemy
        - hit_player    # enemy or hazard damages player
        # Locomotion
        - movement_start
        - movement_stop
        # Jump / gravity
        - jump_start
        - jump_peak
        - land
        - fall
        # Projectile
        - fire
        - hit_wall
        # Scoring
        - score         # score_delta is non-zero on this frame
    notes: "[] when no event occurs; multiple events allowed per frame (e.g. [land, score])"

  score_delta:
    type: integer
    required: false
    default: 0
    notes: "non-zero only when score event is present; negative values allowed for lives-lost deduction"
```

**Constraints:**
- `entity_id` must never contain a copyright-protected proper noun.
- State strings must be drawn exclusively from the `state.enum` list above. Downstream consumers (T10, T11) must use the same list verbatim to avoid ADR-008 naming-drift mismatches.
- Event strings must be drawn exclusively from the `events.enum` list above.
- New states or events must be added to this vocabulary before they can appear in any trace record.

### Fields requiring T10 calibration

These fields are typed and named here but their numeric values must be measured from real gameplay capture in T10. Do not hardcode from ROM analysis.

| Field | Category | Notes |
|-------|----------|-------|
| `velocity_x` (projectile) | projectile | constant; sign from facing direction |
| `velocity_y` (jump initial) | jump_arc | negative; set on jump_start frame |
| `gravity_units_per_frame` | gravity_collision | positive constant |
| `spawn_delay_frames` | projectile | integer; measured input-to-spawn |
