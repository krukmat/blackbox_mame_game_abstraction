## Purpose

Implement the core abstraction step: convert `FrameDiffStat` records (pixel motion data) into `TraceEntry` records (abstract behavioral state) using the canonical vocabulary from T09.2. This is the layer where private pixel observations become public abstract mechanics.

The existing `EntityCandidateBuilder` produces spatial summaries — it does not produce `TraceEntry`. A new `trace_extractor.py` module is required.

## Reference Reasoning

`High`

Reasoning basis:

- the translation contract (FrameDiffStat → velocity → state → events) involves design decisions not derivable from existing code
- state and event naming must match the T09.2 canonical vocabulary exactly — any drift causes false mismatches in `BehavioralDiff.compare` (ADR-008 Known Gap)
- the extractor must use the input plan to correlate fire/jump events with frames where no visual motion is detectable

## Scope

- define and document the translation contract (T10.2.2.1)
- implement `_compute_velocity` and `_assign_state` (T10.2.2.2)
- implement `_infer_events` from state transitions and input plan (T10.2.2.3)
- assemble and verify `extract_trace` end-to-end (T10.2.2.4)

## Out of Scope

- output writing and CLI integration (T10.2.3)
- timing calibration with real values (T10.3)
