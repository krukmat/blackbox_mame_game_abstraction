# T05.2.5 - Final Boundary Synthesis

## Status

Completed

## Purpose

Close `T05.2.5` by deciding whether the `T05.2` redaction policy is implementation-ready for `T05.3`.

## Inputs Reviewed

- `T05.2.5.1 - Policy Artifact Cross-Check`
- `T05.2.5.2 - Surface Consistency Review`
- `T05.2.5.3 - Output Rule Alignment Review`

## Implementation-Blocking Ambiguities

None.

The remaining nuances are implementation constraints, not unresolved policy questions:

- repo-safe relative references must use an explicit allowlist
- sanitized `stdout` and `stderr` must remain path-free and non-evidentiary
- `write_public_metadata` remains the last enforcement gate and must reject unsanitized payloads

## Final Boundary Decision

The `T05.2` policy is implementation-ready.

`T05.3` should proceed without redefining policy, using the following fixed rules:

1. raw private evidence paths never remain public
2. frame and crop paths never remain public
3. ROM paths never remain public
4. absolute local machine paths never remain public
5. `command[*]` may retain only:
   - abstract arguments
   - non-path scalars
   - opaque `private://...` handles
   - explicitly allowlisted repo-safe relative references
6. `preflight.issues[*].message`, `execution.stdout`, and `execution.stderr` may retain only path-free operational meaning after sanitization

## T05.3 Implementation Handoff

`T05.3` should implement, in this order:

1. command-element sanitization
2. preflight-message sanitization
3. execution-output sanitization
4. explicit allowlist handling for repo-safe relative references
5. writer/guardrail enforcement for unsanitized public payloads

## Exit Decision

- `T05.2`: complete
- `T05.2.5`: complete
