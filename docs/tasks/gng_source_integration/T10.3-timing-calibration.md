**movement_tolerance rationale**

GNG native resolution: 256×224 pixels. One abstract unit = one pixel.
- 1.0 unit (old placeholder): too tight — sub-pixel rounding in float arithmetic can exceed it.
- 2.0 units (calibrated): covers integer truncation rounding (max rounding error for `int(x * 16.768)` is < 1 ms → < 0.06 px/ms drift), without masking a real 2-pixel position error.
- Measured frame coordinate range: x ∈ [0, 256], y ∈ [0, 224]; tolerance of 2.0 is < 1% of axis range.

**Fields still pending (require multi-mechanic trace)**

- `velocity_x` (locomotion/projectile): needs frames with sustained walk or in-flight projectile
- `velocity_y` initial (jump): needs frame with `jump_start` event
- `gravity_units_per_frame`: needs ascending + descending frames
- `spawn_delay_frames`: needs fire input followed by projectile spawn

## Purpose

Measure the numeric constants that were marked `calibration-pending` in T09.4 from the real trace produced in T10.2.3. This converts the mechanics schema from a structural definition into a calibrated behavioral specification usable by T11.

## Reference Reasoning

`Medium`

Reasoning basis:

- measurement is mechanical once the trace exists, but requires understanding which frames and entities to measure against
- the four constants (`velocity_x` projectile, `velocity_y` jump initial, `gravity_units_per_frame`, `spawn_delay_frames`) may not all be observable in a single 300-frame capture if the input plan does not trigger every mechanic
- tolerances for `BehavioralDiff.compare` (`movement_tolerance`) must also be decided from the coordinate scale observed in the trace

## Scope

- load trace from T10.2.3 output (`specs/traces/gng_trace.json`)
- measure from trace data:
  - `velocity_x` (projectile): delta x per frame for entity_type `projectile` in `in_flight` state
  - `velocity_y` initial (jump): velocity_y on frame where `jump_start` event appears
  - `gravity_units_per_frame`: delta velocity_y per frame during `ascending`/`descending` states
  - `spawn_delay_frames`: frame count between input `fire` frame and first `projectile` frame
- update `specs/mechanics/gng_abstract_mechanics.yaml` with measured values and `calibration_status: calibrated`
- document measurement method and frame range under `## Calibration Evidence` in this file
