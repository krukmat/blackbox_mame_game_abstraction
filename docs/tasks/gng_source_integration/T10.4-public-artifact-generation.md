# T10.4 - Public Artifact Generation + Guardrails Verification

## Status

✅ Done

## Objective

Produce a fresh, high-quality `specs/traces/gng_trace.json` using the full T10.6 OpenCV pipeline, verify it passes all public-output guardrails and schema validation, and deliver the canonical public artifact that T11 will consume.

## Why This Task Exists

The current `specs/traces/gng_trace.json` was generated before T10.6 (old pipeline, manual_01). It contains ~477k hazard entries and was produced without OpenCV, MOG2 background subtraction, or player gap tolerance. It cannot serve as the T11 input because:

- player detection coverage is too low for physics calibration
- hazard noise (477k entries) dominates the trace
- calibration fields in `gng_abstract_mechanics.yaml` remain `calibration: pending` — they cannot be resolved without a clean, event-rich trace

A fresh MAME capture run is required. Regenerating from existing evidence is not sufficient because:
- `manual_01` was captured before T10.6 was implemented
- `manual_02` (3162 frames) is too short to produce adequate jump+fire+movement coverage for T11.3 calibration

## Scope

- Perform a new GNG manual capture session using the current autoboot + layered plan pipeline
- Extract frames and generate trace with the T10.6 OpenCV backend
- Evaluate trace quality against the minimum thresholds below
- If thresholds are not met, perform additional capture runs until they are
- Verify `specs/traces/gng_trace.json` passes `ensure_public_output_path` and `ensure_no_private_paths`
- Validate against `trace.schema.json`
- Run full Python test suite and confirm no regressions
- Document capture run ID, quality metrics, and schema validation results in `## Artifact Evidence`

## Capture Procedure

### Step 1 — Launch MAME with autoboot

```bash
./scripts/launch_manual_capture_autoboot.sh t10_4_01
```

Play until: Arthur has jumped multiple times, fired multiple times, encountered enemies, and progressed at least partway across stage 1. Minimum 3000 frames of gameplay recommended.

### Step 2 — Extract frames and regenerate trace

```bash
./scripts/extract_frames.sh t10_4_01
```

This regenerates `specs/traces/gng_trace.json` using the OpenCV backend.

### Step 3 — Quality gate

Run the quality check (see Acceptance Criteria). If thresholds are not met, repeat from Step 1 with a new run ID.

## Out of Scope

- Modifying the vision pipeline
- Changing the trace schema
- Connecting to T11 (RN prototype)
- Boot calibration (ADR-018)

## Dependencies

- T10.6 complete (OpenCV backend with MOG2 + gap tolerance — ✅ Done)
- MAME binary, ffmpeg, gng.zip available locally

## Blocks

- T11 (all subtasks)

## Quality Gate — Minimum Thresholds

| Metric | Minimum | Rationale |
|--------|---------|-----------|
| Player detection rate | > 40% of gameplay frames (post frame 1505) | Enough data for T11.3 calibration |
| Player spawn count | ≤ 10 | Indicates good gap-tolerance tuning |
| Hazard entries | < 5,000 | MOG2 + min_contour_area filter working |
| Jump events | ≥ 20 | Enough to calibrate jump arc in T11.3 |
| Fire events | ≥ 30 | Enough to calibrate projectile velocity in T11.3 |
| `ensure_no_private_paths` | passes | Clean-room required |
| Schema validation | passes | T11 consumer requires valid schema |
| Full test suite | all green | No regressions |

## Acceptance Criteria

- New `specs/traces/gng_trace.json` was generated from a capture run performed after T10.6 was merged
- All quality gate thresholds above are met
- `ensure_public_output_path` passes for `specs/traces/gng_trace.json`
- `ensure_no_private_paths` passes for the full trace payload
- `specs/traces/gng_trace.json` validates against `trace.schema.json`
- Full Python test suite passes
- `## Artifact Evidence` section below is populated with capture run ID, quality metrics, and SHA-256
