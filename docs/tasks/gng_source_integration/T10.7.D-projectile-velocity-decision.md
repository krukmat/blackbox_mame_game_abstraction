# T10.7.D — Projectile Velocity: Accept Surrogate or Plan In-Flight Tracking

## Status

✅ Complete — Option B selected on 2026-05-23. Surrogate acceptance rejected; real in-flight tracking required before projectile calibration can be treated as measured.

## Parent Task

[T10.7 — Tracker Continuity Fix](./T10.7-tracker-continuity-fix.md) — scoping decision for `projectile_velocity_x` calibration.

## Objective

Resolve the open question on `projectile_velocity_x` before T11.4 begins. The current value is a surrogate (player velocity at fire events) and is inconsistent between files (0.1871/s in calibration YAML vs 8.5348/s in mechanics YAML, both surrogates from different traces). This task produces a documented, intentional choice — either accepting the limitation until T12 or creating a plan for real in-flight projectile tracking.

## Context

The ADR-013 Known Gap states: *"Cross-frame enemy ID continuity is not implemented — enemies remain ephemeral per-frame entities."* The same applies to projectiles: the vision layer does not track a projectile across consecutive frames. Without per-frame projectile positions, there is no direct `velocity_x` measurement available.

Current values:
- `gng_physics_calibration.yaml`: `projectile_velocity_x = 0.1871/s` (n=21, player velocity at fire events from `run_t10_7_jumps` — jump-only trace, almost no fire events)
- `gng_abstract_mechanics.yaml`: `projectile_velocity_x = 8.5348/s` (n=54, T11.3, player velocity at fire events from a fuller trace)
- Both values use the same surrogate method; neither is a real projectile measurement
- For T11.4 (Episode-Driven Scene), the scene focuses on movement and jump arcs — projectile firing is not required in the first episode scene implementation

## Options

### Option A — Accept surrogate until T12 (Recommended for T11.4)

- Document the surrogate explicitly in `gng_physics_calibration.yaml` and `gng_abstract_mechanics.yaml`
- Resolve the file inconsistency by keeping the T11.3 value (8.5348/s, n=54 — more fire events, same method, more representative)
- Add a `calibration_method: surrogate_accepted` note and a `defer_to: T12` marker
- No new ADR required (the gap is already documented in ADR-013)
- **Impact on T11.4:** none — the episode scene does not require accurate projectile velocity
- **Impact on T12:** projectile calibration becomes a T12 prerequisite if the scene involves firing

### Option B — Plan in-flight projectile tracking

- Implement a new vision layer component that tracks projectile blobs across frames
- Requires new entity continuity logic in `trace_extractor.py` (cross-frame ID assignment for small fast-moving blobs)
- Would need a new ADR (new tracking pattern, new entity continuity contract)
- Estimated effort: **L** — projectiles are small, fast, and frequently off-screen mid-frame
- **Blocks T11.4** unless parallelized with a separate agent
- Only needed if T11.4 scene requires accurate projectile physics

## Scope

- Review both values, decide on Option A or B
- If Option A: update calibration YAML + mechanics YAML to resolve the inconsistency (keep T11.3 value with surrogate note)
- If Option B: create a new task file for projectile tracking + ADR
