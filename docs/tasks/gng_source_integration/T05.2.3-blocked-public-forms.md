# T05.2.3 - Blocked Public Forms

## Status

Completed

## Purpose

Define which values must never appear in harness public metadata, even when embedded inside command arguments, validation messages, or process output.

## Blocked Public Forms

### B1. Raw private evidence paths

Blocked form:

- any path under `evidence/private/...`

Why blocked:

- directly discloses private local evidence structure
- violates the clean-room public-output boundary

Blocked sensitive classes:

- `S1 Private evidence path`

### B2. Frame paths

Blocked form:

- any path that directly references frame directories or frame files

Why blocked:

- reveals private capture internals
- public outputs must not expose frame paths

Blocked sensitive classes:

- `S2 Frame path`

### B3. Crop paths

Blocked form:

- any path that directly references crops or crop files

Why blocked:

- public outputs must not expose crop references
- crop references imply derivative visual handling that the repo explicitly avoids

Blocked sensitive classes:

- `S3 Crop path`

### B4. Direct ROM paths

Blocked form:

- any path that directly reveals ROM storage, ROM directory layout, or the location of `gng.zip`

Why blocked:

- public metadata must not disclose ROM placement or ROM filenames as filesystem references
- ROM locations are private local setup details

Blocked sensitive classes:

- `S4 Direct ROM path`

### B5. Absolute local machine paths

Blocked form:

- any absolute path that reveals machine-local filesystem structure

Why blocked:

- discloses local machine environment details unrelated to public output
- can expose usernames, temp directories, project layout, or external storage locations

Blocked sensitive classes:

- `S5 Absolute local machine path`

### B6. Unsanitized path-bearing process output

Blocked form:

- any `execution.stdout` or `execution.stderr` content that still contains blocked path forms

Why blocked:

- the process-output container does not make the path disclosure acceptable
- human-readable output is only allowed after sanitization

Blocked sensitive classes:

- `S1`
- `S2`
- `S3`
- `S4`
- `S5`
- relevant `S6` cases

### B7. Unsanitized path-bearing validation messages

Blocked form:

- any `preflight.issues[*].message` content that still contains blocked path forms

Why blocked:

- the validation-message container does not make the path disclosure acceptable
- validation detail must be preserved without exposing local paths

Blocked sensitive classes:

- `S1`
- `S2`
- `S3`
- `S4`
- `S5`
- relevant `S6` cases

## Conditionally Blocked Form

### B8. Non-private workspace paths that are not clearly public repo-safe references

Blocked form:

- repo-relative or workspace-relative paths that are not explicitly public-safe under `T05.2.2`

Why blocked by default:

- a non-private workspace path can still reveal local execution structure or helper layout
- only explicitly public repo-safe references are allowed

Blocked sensitive classes:

- `S6 Non-private workspace path in public runtime payload`

Exception path:

- these values may only survive if they satisfy an allowed public form from `T05.2.2`

## Blocked-Form Summary By Field

- `command[*]` must never contain:
  - raw private evidence paths
  - frame paths
  - crop paths
  - direct ROM paths
  - absolute local machine paths
  - non-approved workspace paths

- `preflight.issues[*].message` must never contain:
  - raw private evidence paths
  - frame paths
  - crop paths
  - direct ROM paths
  - absolute local machine paths
  - non-approved workspace paths

- `execution.stdout` and `execution.stderr` must never contain:
  - raw private evidence paths
  - frame paths
  - crop paths
  - direct ROM paths
  - absolute local machine paths
  - non-approved workspace paths

## Boundary Rule

A value is blocked if it:

1. directly exposes private evidence structure
2. directly exposes ROM storage or ROM zip location
3. directly exposes local machine filesystem structure
4. exposes frame or crop references
5. remains path-bearing inside a public human-readable message or process output
6. is a workspace-relative path that has not been explicitly allowed as repo-safe

If a value is blocked, it must not remain verbatim in public metadata. `T05.2.4` must therefore assign it either:

- `replace` with an allowed public form, or
- `block` as non-publicable content
