## Purpose

The `FrameDiffer` currently produces one bounding box per frame — the union of all changed pixels. When multiple entities are on screen simultaneously, this merges player, enemies, and projectiles into a single blob. `TraceExtractor` then classifies that blob by area ratio, producing one wrong `TraceEntry` instead of separate correct entries per entity.

T10.5 introduces `ArthurTracker`, which uses a geometric signature (sprite height range, vertical center position) to isolate the player character from the frame diff before classifying remaining regions as enemies or projectiles.

This is the prerequisite for multi-entity traces. Without it, T10.4 public artifact and T11 RN hookup consume a trace that cannot distinguish Arthur from an enemy standing next to him.

## Architectural Decision

This task introduces ADR-012 (Entity Signature-Based Player Identification). Read that ADR before touching any module in this task.

## T10.5-A — Multi-region FrameDiffer

### Status
✅ Done

### Purpose
Replace the single global bounding box in `FrameDiffer._diff_pair` with connected-component labeling that produces one `MotionBox` per independent motion blob.

### Scope
- Implement connected-component labeling (4-connectivity flood fill) over the set of changed pixels in `_diff_pair`.
- Each connected component → one `MotionBox` with its own `(x, y, width, height, center_x, center_y)`.
- `FrameDiffStat.changed_regions` is already `list[MotionBox]` — the type contract does not change.
- Existing callers that only look at `changed_regions[0]` remain valid; they now get the largest component instead of the global box.
- Minimum component size: 4 pixels. Smaller components are noise and discarded.

### Out of Scope
- 8-connectivity labeling.
- Tracking component identity across frames (that belongs to T10.5-B).
- Any change to `FrameDiffStat` fields or `to_public_dict`.

### Dependencies
None.

### Reasoning Grade
`Medium` — flood fill is well-understood, but must be correct under edge cases (single pixel, full-frame change, touching components) and must not regress existing tests.

### Effort Grade
`M`

### Recommended Model
`Sonnet`

### Acceptance Criteria
- `FrameDiffer.diff_manifest` on a two-frame manifest where pixels change in two non-adjacent rectangular regions returns a `FrameDiffStat` with `len(changed_regions) == 2`.
- Existing single-blob behavior still passes (all tests green).
- No path strings in output (ADR-006).
- Minimum component filter: a region of 3 pixels is discarded; a region of 4 pixels is kept.

## T10.5-B — ArthurSignature + ArthurTracker

### Status
✅ Done

### Purpose
Introduce `ArthurSignature` (configurable geometric constraints) and `ArthurTracker` (region matcher that identifies the player entity from a list of `MotionBox` candidates).

### Scope
- New file: `packages/vision/arthur_tracker.py`
- `ArthurSignature(slots=True)`:
  - `height_min_px: int = 24`
  - `height_max_px: int = 36`
  - `center_y_min_px: int = 155`
  - `center_y_max_px: int = 195`
- `ArthurTracker`:
  - `find_arthur(regions: list[MotionBox], sig: ArthurSignature, prev_center: tuple[float, float] | None = None) -> MotionBox | None`
    - Filters by `sig.height_min_px <= region.height <= sig.height_max_px`
    - Filters by `sig.center_y_min_px <= region.center_y <= sig.center_y_max_px`
    - When multiple candidates pass, returns the one with minimum Euclidean distance from `prev_center` (nearest-neighbor).
    - Returns `None` if no candidate passes.
  - `track_sequence(diffs: list[FrameDiffStat], sig: ArthurSignature) -> list[MotionBox | None]`
    - Applies `find_arthur` per frame, carrying the last-known center as `prev_center`.
    - Returns one entry per diff (same length as input).

### Out of Scope
- Generic `PlayerTracker(signature)` abstraction (deferred per ADR-012).
- Any velocity or state computation (that is TraceExtractor's domain).

### Dependencies
- T10.5-A (needs multi-region `FrameDiffStat`).

### Reasoning Grade
`Medium` — nearest-neighbor tracking is well-defined, but the signature numeric values must be justified against GNG's pixel layout.

### Effort Grade
`M`

### Recommended Model
`Sonnet`

### Acceptance Criteria
- `find_arthur` returns `None` for an empty region list.
- `find_arthur` returns `None` when all regions fail the height filter.
- `find_arthur` returns `None` when all regions fail the center_y filter.
- When two regions both qualify, `find_arthur` returns the one closer to `prev_center`.
- `track_sequence` returns a list of same length as `diffs`.
- All output is numeric (no path strings).

### T10.5-C.1 — Player isolation in extract_trace

#### Status
✅ Done

#### Purpose
Wire `ArthurTracker` into `extract_trace` so the player region is identified and emitted as `entity_id = "player"`. Non-player regions are not yet processed in this subtask.

#### Scope
- Import `ArthurTracker` and `ArthurSignature` in `trace_extractor.py`.
- At the top of the per-frame loop: call `ArthurTracker.find_arthur(curr_stat.changed_regions, sig)`.
- If a player region is found, emit one `TraceEntry` with `entity_id = "player"`, `entity_type = "player"`, and the existing Rule 1–4 logic applied to that region.
- If `find_arthur` returns `None`, skip emitting a player entry for that frame (gap in player trace is acceptable per ADR-012).
- Leave non-player regions unprocessed (handled in C.2).
- Remove the legacy single-region primary-blob player path that existed before.

#### Out of Scope
- Non-player region classification (C.2).
- Per-entity state isolation (C.3).
- Multi-entity spawn/die logic (C.4.a–C.4.c.2.b).

#### Dependencies
- T10.5-A (multi-region `FrameDiffStat`)
- T10.5-B (`ArthurTracker.find_arthur`)

#### Reasoning Grade
`Low` — mechanical wiring of an already-designed interface.

#### Effort Grade
`S`

#### Recommended Model
`Sonnet`

#### Acceptance Criteria
- `extract_trace` emits a player entry for frames where `find_arthur` succeeds.
- `extract_trace` emits no player entry for frames where `find_arthur` returns `None`.
- All existing tests pass (243 baseline green).

### T10.5-C.2 — Remaining regions → TraceEntry

#### Status
✅ Done

#### Purpose
After the player region is claimed by `find_arthur`, classify and emit `TraceEntry` records for all remaining regions using `_entity_type_from_box`.

#### Scope
- After calling `find_arthur`, collect the list of regions not matched as the player.
- For each remaining region: call `_entity_type_from_box` → entity_type; `_entity_id_from_type(entity_type, frame)` → entity_id.
- Apply Rule 1–4 velocity/state/event logic for each region using that region's own center as the motion baseline.
- Emit one `TraceEntry` per remaining region.

#### Out of Scope
- Per-entity prev_state isolation (C.3) — at this point, prev_state lookup still uses the existing `for entry in reversed(entries)` pattern.
- Multi-entity spawn/die rewrite (C.4.a–C.4.c.2.b).

#### Dependencies
- T10.5-C.1

#### Reasoning Grade
`Medium` — straightforward loop, but per-region velocity baseline requires careful prev-frame region matching.

#### Effort Grade
`S`

#### Recommended Model
`Sonnet`

#### Acceptance Criteria
- A frame with one player-signature region and one enemy region produces two `TraceEntry` records.
- A frame where `find_arthur` returns `None` still produces entries for non-player regions.
- All state/event strings are canonical T09.2 vocabulary.
- All existing tests pass.

### T10.5-C.3 — Per-entity prev_state tracking

#### Status
✅ Done

#### Purpose
Replace the shared `for entry in reversed(entries)` prev_state lookup with a per-entity-id dict so that state does not bleed between the player and enemies on the same frame.

#### Scope
- Introduce `prev_state_by_entity: dict[str, str]` keyed by `entity_id`.
- After emitting each `TraceEntry`, write `prev_state_by_entity[entity_id] = curr_state`.
- Replace the reverse-scan lookup with `prev_state_by_entity.get(entity_id, "idle")`.
- Rule 1 velocity: the prev-frame region for each entity must also be tracked independently. Introduce `prev_region_by_entity: dict[str, MotionBox]` — updated after each entity's entry is emitted.
- Enemies use ephemeral IDs (`enemy_a_{frame}`) — they will rarely have a prev entry, so they default to `"idle"` and zero velocity. This is the correct behavior per ADR-008.

#### Out of Scope
- Cross-frame enemy identity continuity (out of scope per ADR-008).
- Spawn/die rewrite (C.4.a–C.4.c.2.b).

#### Dependencies
- T10.5-C.2

#### Reasoning Grade
`High` — subtle correctness requirement: per-entity state isolation interacts with ephemeral enemy IDs and must not break the player trace across frames.

#### Effort Grade
`M`

#### Recommended Model
`Sonnet`

#### Acceptance Criteria
- Player state is computed from the player's own previous center, not from whatever entity appeared last in `entries`.
- Enemy state is computed from its own previous region (defaults to `idle` / zero velocity when no prior entry exists).
- All existing and new tests pass.

### T10.5-C.4.b — Multi-entity spawn emission

#### Status
✅ Done

#### Purpose
Use `prev_seen_by_id` to emit correct `spawn` events independently for the player and for each ephemeral enemy entity.

#### Scope
- Player: `entity_id = "player"` — persistent; `spawn` emitted exactly once on first appearance across the full trace.
- Enemies: `entity_id = "enemy_a_{frame}"` — ephemeral; `spawn` emitted on every first appearance because each new frame-level enemy ID is a new entity.
- A frame with multiple enemy regions produces one independent `spawn` decision per region.
- Do not change die annotation behavior in this subtask.

#### Out of Scope
- Cross-frame enemy identity continuity.
- Die annotation rewrite.
- Changing the `TraceEntry` schema.

#### Dependencies
- T10.5-C.4.a

#### Reasoning Grade
`Medium` — event emission is straightforward once presence is keyed by `entity_id`, but player persistence and ephemeral enemy IDs must stay distinct.

#### Effort Grade
`S`

#### Recommended Model
`Sonnet`

#### Acceptance Criteria
- Player receives exactly one `spawn` event across the full trace (on its first frame).
- Each enemy region receives a `spawn` on the frame it appears.
- A frame with two enemy regions produces two independent spawn decisions without interference.
- Baseline and new tests stay green up to spawn expectations.
