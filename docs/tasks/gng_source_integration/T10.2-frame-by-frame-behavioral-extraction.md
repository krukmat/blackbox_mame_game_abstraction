## Purpose

Convert private evidence from T10.1.3 into a sequence of `TraceEntry` records using the canonical vocabulary from T09.2. This is the abstraction step: private video/frame evidence becomes abstract behavioral state, with no private paths or pixel values in the output.

## Reference Reasoning

`High`

Reasoning basis:

- the existing vision pipeline (`EntityCandidateBuilder`) produces `EntityCandidate`, not `TraceEntry` — a new translator layer is required
- `FrameManifest.from_run` only reads `.pgm` files, but the real T10.1.3 gameplay evidence is an AVI capture (`video/capture.avi`) plus a single startup PNG snapshot — format compatibility and extraction strategy must be resolved first
- the translation contract (FrameDiffStat → velocity → state → events) involves design decisions that affect T10.3 calibration and T11 validation

## Scope

- determine how private gameplay frames are materialized from the real MAME evidence source (`capture.avi`)
- fix frame format compatibility so the manifest can read the extracted real MAME frames
- implement `trace_extractor.py` that produces `TraceEntry` records from `FrameDiffStat`
- serialize the trace to a public JSON file via a new `extract-trace` CLI subcommand
- all output must pass `ensure_public_output_path` and `ensure_no_private_paths`

## Out of Scope

- timing calibration with real values (T10.3)
- public artifact generation (T10.4)
