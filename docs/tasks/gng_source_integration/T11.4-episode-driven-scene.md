# T11.4 — Episode-Driven Scene in RN Prototype

## Status

🔲 Planned

## Parent Task

[T11 — RN Prototype Hookup](./T11-rn-prototype-hookup.md)

## Objective

Load the public episode artifact into the RN prototype and replace the remaining
hardcoded playable-scene bootstrap with a scene derived from real public episode
data and calibrated mechanics.

## Scope

- Add `apps/rn-prototype/src/specs/episodeLoader.ts`
  - load `specs/episodes/gng_episodes.json`
  - return typed episode structures for RN consumption
  - validate the minimum required player/frame shape for runtime use
- Extend scene creation in the RN prototype
  - add `createEpisodeScene(episode)` or equivalent scene-construction path
  - derive initial entity kind, position, and velocity from episode frame data
  - stop relying on hardcoded sample positions for the main playable scene path
- Update the game-loop path so episode playback can advance deterministically
  frame by frame from public episode data
- Wire the scene path to the calibrated mechanics already loaded through
  `mechanicsLoader.ts`
- Add or update focused RN tests for the loader and scene bootstrap behavior

## Out of Scope

- T12 product-direction work or original game-definition artifacts
- Touch input, mobile UX, menus, or app-shell work
- New Python artifact generation
- Recalibration, trace regeneration, or episode regeneration
- Clean-room verification sweep across the whole RN app (that is T11.5)

## Dependencies

- ✅ T11.1 complete — mechanics YAML loader exists
- ✅ T11.2 complete — `specs/episodes/gng_episodes.json` exists
- ✅ T11.3 complete in the superseded-then-remediated sense: canonical physics
  values now come from the T10.7-synced calibration chain
- ✅ T10.7 ST5/ST6 complete — public mechanics and episodes are in sync and
  documentation reflects the post-remediation state

## Reasoning Grade

`Medium`

Reasoning basis: this is a runtime-integration task across public artifacts,
TypeScript loaders, and scene bootstrap behavior. The data flow is clear, but
the implementation still has to preserve the clean-room boundary and fit the
existing RN engine structure.

## Effort Grade

`Medium`

## Recommended Model

`gpt-5.4`

## Acceptance Criteria

1. `episodeLoader.ts` loads `specs/episodes/gng_episodes.json` without runtime
   error from the RN prototype context.
2. The RN prototype can build a scene from real episode data instead of the
   current hardcoded sample bootstrap.
3. Initial entity state in the episode scene is derived from the loaded public
   episode payload, not hardcoded coordinates or velocities.
4. Episode playback advances deterministically through the loaded frame data.
5. The mechanics values used by the scene path come from the existing public
   mechanics/calibration flow, not new hardcoded physics constants.
6. No RN-side import path reaches into `evidence/private/`, ROM paths, frame
   directories, or other private artifacts.
7. Focused RN tests covering loader and scene bootstrap behavior pass.
