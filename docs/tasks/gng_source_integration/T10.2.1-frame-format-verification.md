## Purpose

Ensure the vision pipeline can read the frame evidence produced by the real MAME capture. `FrameManifest.from_run` currently does `glob("*.pgm")`, but T10.1.3 established that the real gameplay evidence is `video/capture.avi` while `frames/` contains only a startup PNG snapshot. This gate must be cleared before `FrameDiffer` can run on real evidence.

## Reference Reasoning

`High`

Reasoning basis:

- the format mismatch is a silent failure: the manifest returns an empty frame list, the differ produces no stats, and no error is raised
- the input-source mismatch is also a pipeline design issue: decide whether T10.2 consumes extracted PNGs, another intermediate private format, or direct video decode
- extending the manifest to support the chosen extracted format requires maintaining the private-path guardrail on every loaded frame
- existing PGM tests must not regress

## Scope

- audit the actual private evidence layout produced by the T10.1.3 gameplay run
- decide and document the private frame materialization strategy from `capture.avi`
- extend `frame_manifest.py` only after the materialized frame format is confirmed
- verify regression gate: PGM tests still pass, new format has coverage

## Out of Scope

- motion extraction or TraceEntry production (T10.2.2)

## Dependencies

- T10.1.3

## Blocks

- T10.2.2.1

## Acceptance Criteria

- T10.2.1.1 documents the real evidence source, output layout, and the chosen extraction/materialization strategy
- `FrameManifest.from_run` returns a non-empty frame list for the chosen private extracted-frame directory after T10.2.1.2
- all frames pass `ensure_private_evidence_path` before being added to the manifest
- 118+ tests pass with no regressions
