# T05.2 - Unified Redaction Policy Subtasks

## Parent Task

- `T05.2 - Unified Redaction Policy`

## Parent Cataloging

- Reasoning grade: `High`
- Effort grade: `Medium`
- Recommended model: `gpt-5.4`

## Cataloging Rationale

`T05.2` remains `High` because it defines the clean-room public-output boundary for the harness. The task decides one coherent policy across `command`, `preflight`, and `execution`, and mistakes here can leak private evidence or local machine details into public metadata.

## Subtasks

### T05.2.1 Sensitive Surface Inventory Consolidation

- Objective: consolidate the `T05.1` audit into one normalized inventory of sensitive value classes and affected public fields.
- Scope:
  - `command[*]`
  - `preflight.issues[*].message`
  - `execution.stdout`
  - `execution.stderr`
  - any other string fields written by `handle_run`
- Out of scope:
  - defining final replacement or blocking rules
- Dependencies:
  - `T05.1`
- Reasoning grade: `Medium`
- Effort grade: `Low`
- Recommended model: `gpt-5.4-mini`
- Acceptance criteria:
  - all relevant sensitive value classes are listed once
  - all affected public fields are listed once

### T05.2.2 Allowed Public Forms

- Objective: define which public forms are allowed to remain in public metadata.
- Scope:
  - opaque handles such as `private://...`
  - abstract or repo-safe relative references that do not expose private evidence or ROM locations
- Out of scope:
  - blocked-value policy
- Dependencies:
  - `T05.2.1`
- Reasoning grade: `Medium`
- Effort grade: `Low`
- Recommended model: `gpt-5.4-mini`
- Acceptance criteria:
  - allowed public forms are defined unambiguously
  - the policy distinguishes allowed handles from leaked local paths

### T05.2.3 Blocked Public Forms

- Objective: define which values must never appear in public metadata.
- Scope:
  - direct ROM paths
  - frame paths
  - crop paths
  - absolute local machine paths
  - raw private evidence paths
- Out of scope:
  - implementation details of how to sanitize them
- Dependencies:
  - `T05.2.1`
- Reasoning grade: `Medium`
- Effort grade: `Low`
- Recommended model: `gpt-5.4-mini`
- Acceptance criteria:
  - blocked forms are defined explicitly
  - no sensitive value class from `T05.2.1` is left uncategorized

### T05.2.4 Redaction Decision Table

- Objective: define one action per sensitive value class: allow, replace, or block.
- Scope:
  - decision mapping for every sensitive class and every affected public field
- Out of scope:
  - code changes
- Dependencies:
  - `T05.2.2`
  - `T05.2.3`
- Reasoning grade: `Medium`
- Effort grade: `Low`
- Recommended model: `gpt-5.4-mini`
- Acceptance criteria:
  - each sensitive value class has exactly one public handling rule
  - the decision mapping covers `command`, `preflight`, and `execution`

### T05.2.5 Boundary Consistency Review

- Objective: verify that the full redaction policy is coherent and satisfies the repo output rule.
- Scope:
  - cross-check the final policy against `AGENTS.md`, `CLAUDE.md`, `README.md`, and the `T05.1` audit
- Out of scope:
  - implementation and test execution
- Dependencies:
  - `T05.2.4`
- Reasoning grade: `High`
- Effort grade: `Low`
- Recommended model: `gpt-5.4`
- Acceptance criteria:
  - the final policy has no contradictions across surfaces
  - the final policy preserves the clean-room public-output boundary
