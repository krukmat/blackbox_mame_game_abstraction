# T10.8.5 — Trace Regeneration and Quality Validation

## Status

🔲 Planned — awaiting parent-task approval.

## Parent Task

[T10.8 — Enemy Tracking Continuity](./T10.8-enemy-tracking-continuity.md)

## Objective

Regenerate `specs/traces/gng_trace.json` from `evidence/private/run_t10_4_01/frames/` using the post-T10.8.3 vision pipeline, then verify the output against the quality gates defined in `T10.8` Acceptance Criterion #6. If a gate fails, T10.8 is not complete and investigation must precede commit.

## Scope

- Re-run `vision_pipeline.extract_run_trace` (or equivalent CLI entry point) on `run_t10_4_01`.
- Replace `specs/traces/gng_trace.json` with the regenerated output.
- Compute and report the validation gates:
  1. **Per-track duration gate**: ≥ 80% of non-player tracks have `last_seen_frame - spawn_frame + 1 ≥ 5`.
  2. **Spawn-count plausibility gate**: total `spawn` events per non-player `entity_type` ≤ 30 over the full run.
  3. **Lifecycle closure gate**: every non-player track has either a `die` event or `last_seen_frame == run_end_frame`.
  4. **Bounded-duration gate**: no track has `last_seen_frame - spawn_frame + 1 > run_length`.
- Diff the new trace against the prior `gng_trace.json` and document the structural changes in a short report appended to `docs/handoff_t11_3_physics_calibration.md` (so consumers see what shifted before T11.2 re-runs).
- Run `ensure_no_private_paths` on the regenerated trace as a final guardrail.

## Out of Scope

- Re-running `physics_calibrator.py` or `episode_extractor.py` — those are downstream consumers covered by T10.8.6 sync + T11.2.
- Updating the RN prototype — covered by T11.4.
- Adjusting validation thresholds based on real-data noise — if a threshold needs tuning, that is an explicit decision documented in the report, not a silent change.
- Capturing new MAME runs — existing `run_t10_4_01` frames are the canonical input.

## Dependencies

- ✅ T10.8.3 — `extract_trace` integration in place.
- ✅ T10.8.4 — regression tests passing.

`Medium`

- Empirical validation step introduces completion-criteria uncertainty — a gate failure may indicate a real issue or a threshold mis-set, and distinguishing them requires evidence interpretation.

## Acceptance Criteria

1. `specs/traces/gng_trace.json` is regenerated and committed.
2. All four validation gates pass; numeric values are recorded in the report.
3. Diff report appended to `docs/handoff_t11_3_physics_calibration.md` summarizing the structural changes (counts of `spawn`, `die`, distinct `entity_id` values, distribution of track durations).
4. `ensure_no_private_paths` passes on the regenerated trace.
5. If any gate fails, T10.8.5 is incomplete — file an investigation note in the report and do not proceed to T10.8.6.
