# T10.8.2 — EntityTracker Generalization

## Status

🔲 Planned — awaiting parent-task approval.

## Parent Task

[T10.8 — Enemy Tracking Continuity](./T10.8-enemy-tracking-continuity.md)

## Objective

Introduce a generalized `EntityTracker` in `packages/vision/entity_tracker.py` that supports concurrent multi-entity multi-type tracking, then refactor `ArthurTracker` to be a thin backward-compatible wrapper over it. The new tracker is the single source of truth for cross-frame identity in the vision layer; ADR-021 documents the design.

## Scope

- Create `packages/vision/entity_tracker.py` with:
  - `EntitySignature` dataclass (entity_type, geometric bounds, `max_frame_jump_px`, `gap_tolerance_frames`).
  - `TrackedEntity` dataclass (entity_id, signature_type, region, last_position, spawn_frame, last_seen_frame, missing_frames).
  - `StepResult` dataclass (tracked, spawned, died).
  - `EntityTracker` class with `__init__(signatures)` and `step(regions, frame) -> StepResult`.
- Matching algorithm:
  - For each region, compute compatible signatures by bounds.
  - For each active track, find compatible candidate regions within `signature.max_frame_jump_px` of `last_position`.
  - Greedy assignment ordered by track `spawn_frame` ascending (oldest first).
  - Unmatched regions become new tracks; allocate `entity_id = f"{signature.entity_type}_{frame}_{spawn_index}"`.
  - Unmatched tracks increment `missing_frames`; close when `missing_frames > signature.gap_tolerance_frames` and append to `StepResult.died`.
- Refactor `packages/vision/arthur_tracker.py`:
  - `ArthurSignature` becomes an `EntitySignature` instance preserving all current defaults.
  - `ArthurTracker.__init__` builds an internal `EntityTracker([ArthurSignature()])`.
  - `find_arthur(regions, sig, prev_center)` continues to return `MotionBox | None`; under the hood it delegates to a single-frame `step` call and unwraps the player track.
  - `track_sequence(diffs, sig)` continues to return `list[MotionBox | None]`; same delegation.
- All existing `packages/vision/tests/test_arthur_tracker.py` tests pass unchanged.
- New regression tests live in `packages/vision/tests/test_entity_tracker.py`.

## Out of Scope

- Hungarian/optimal assignment — greedy is the chosen algorithm per ADR-021.
- Velocity-aware prediction beyond zero-order (`last_position` only). First-order prediction is deferred until validation requires it.
- Per-entity occlusion modelling beyond `gap_tolerance_frames`.
- Loading enemy signatures from YAML — that happens in T10.8.3 inside `extract_trace`.
- Changes to `FrameDiffer`, `gng_vision_config.py` semantics, or HUD masking.

## Dependencies

- ✅ T10.8.1 — `EnemySignature` calibration output is consumed by T10.8.3 but not by this subtask; `EntityTracker` itself is signature-agnostic and can be developed and tested with synthetic signatures.

## Acceptance Criteria

1. `packages/vision/entity_tracker.py` exists with the dataclasses and class as specified.
2. `step()` returns a `StepResult` with correctly populated `tracked`, `spawned`, and `died` lists.
3. `ArthurTracker.find_arthur` and `ArthurTracker.track_sequence` retain their exact public signatures and return values.
4. All existing `packages/vision/tests/test_arthur_tracker.py` tests pass unchanged.
5. New tests in `packages/vision/tests/test_entity_tracker.py` cover:
   - Single-signature single-entity track lifecycle (spawn, persist, die).
   - Single-signature multi-entity concurrent tracks (no ID swap when separated).
   - Multi-signature multi-type concurrent tracks (player + enemy).
   - Velocity-ceiling rejection: candidate beyond `max_frame_jump_px` does not match.
   - Gap tolerance: track persists across `gap_tolerance_frames` gaps; closes after.
   - First-frame allocation: no prev tracks, all regions become new spawns.
   - Empty-frame handling: no candidates → all active tracks increment `missing_frames`.
6. No new public path strings or private path references introduced.
7. `pytest packages/vision/tests/` passes in full.
