## Research Findings

### Per-Frame Callback API

| API path | Status | Notes |
|---|---|---|
| `emu.add_machine_frame_notifier(fn)` | **Confirmed working** | Canonical per-frame hook since ≥0.285. Returns a notifier subscription. Used in `plugins/cheat/init.lua:808` in MAME's own codebase. |
| `emu.register_frame(fn)` | **Deprecated / removed** | Old API, removed in 0.285+. Do not use. |
| `emu.register_frame_done(fn, "frame")` | **Confirmed present** | Secondary hook fired after frame rendering is complete (after `add_machine_frame_notifier`). Used for visual overlays. Available but not needed for frame counting. |
| `emu.framecount()` | **Confirmed nil** | Removed in MAME 0.287. Confirmed broken in T08.2.5. |
| `emu.wait_next_frame(...)` | **Confirmed present** | Coroutine yield utility — yields until next frame. Only usable inside a coroutine, not in a fire-and-forget notifier. Not suitable for our use case. |

### Frame Number Access

| API path | Status | Notes |
|---|---|---|
| `manager.machine.screens[':screen']:frame_number()` | **Confirmed working** | Correct syntax: screen is a device, `frame_number` is a **method call** (colon syntax). Increments monotonically each frame interval. Read-only. |
| `manager.machine.screens[':screen'].frame_number` | **Confirmed nil** | Dot-property access does NOT work — `frame_number` is a method, not a plain Lua property. This is the root cause of the nil bug in T08.2.5. |
| `manager.machine.video.frame_number` | **Confirmed nil** | `video_manager` class has no `frame_number` property. The frame counter lives on the screen device, not the video manager. |
| `manager.machine.video.frame_number()` | **Unknown / likely nil** | `video_manager` has no such method in the 0.287 docs. Not worth testing. |

### Screen Tag for GNG / gngb

The screen tag must be verified at runtime, but standard CPS1/arcade hardware uses `':screen'` as the primary screen tag. The cheat plugin uses:
```lua
for tag, screen in pairs(manager.machine.screens) do
    -- tag will be ':screen' for most arcade games
end
```

### Chosen Signal Channel: stdout via `print()`

**Decision: stdout `print()`**

Rationale: The Python harness already parses `blackbox_harness:start` and `blackbox_harness:stop` from MAME stdout (confirmed working in T08.2.5). Extending the same channel with `blackbox_harness:frame:<N>` requires no new IPC mechanism, no file cleanup, no socket lifecycle management, and no permission changes. stdout is synchronous with MAME's process stdout pipe that the harness already holds open.

Signal format:
```
blackbox_harness:frame:<frame_number>
```

Example: `blackbox_harness:frame:142`

### Canonical Pattern for T10.1.1.2

```lua
-- Hold the subscription to keep it alive
local frame_sub = emu.add_machine_frame_notifier(function()
    local screen = manager.machine.screens[':screen']
    if screen then
        print("blackbox_harness:frame:" .. screen:frame_number())
    end
end)
```
