# T05.2.5.3 - Output Rule Alignment Review

## Status

Completed

## Purpose

Validate that the `T05.2` policy artifacts align with the repo output rule and the documented clean-room guardrails.

## Alignment Checks

### 1. Public output must stay abstract

Source documents:

- `README.md`
- `AGENTS.md`
- `CLAUDE.md`

Policy alignment:

- `T05.2.2` allows only abstract scalars, opaque handles, repo-safe references, and path-free messages
- `T05.2.3` blocks filesystem-bearing forms that would make metadata concrete in the wrong way
- `T05.2.4` routes sensitive values to `replace` or `block`, not raw retention

Result:

- aligned

### 2. Private evidence must never leak into public specs

Source documents:

- `README.md`
- `docs/legal_guardrails.md`
- `AGENTS.md`

Policy alignment:

- `T05.2.1` identifies private evidence paths as `S1`
- `T05.2.2` permits only `private://...` handles as the public-safe representation
- `T05.2.3` blocks raw private evidence paths
- `T05.2.4` marks `S1` as `replace` across runtime-facing public fields

Result:

- aligned

### 3. Frame paths and crop paths are forbidden in public output

Source documents:

- `README.md`
- `docs/legal_guardrails.md`
- `AGENTS.md`
- `CLAUDE.md`

Policy alignment:

- `T05.2.1` identifies frame paths as `S2` and crop paths as `S3`
- `T05.2.3` blocks both classes
- `T05.2.4` ensures they never remain verbatim in public-facing fields

Result:

- aligned

### 4. ROM locations and ROM storage details are non-public

Source documents:

- `README.md`
- `AGENTS.md`
- `CLAUDE.md`
- `docs/legal_guardrails.md`

Policy alignment:

- `T05.2.1` identifies direct ROM paths as `S4`
- `T05.2.2` does not permit ROM paths as public forms
- `T05.2.3` blocks direct ROM paths
- `T05.2.4` assigns `replace` to preserve only sanitized operational meaning

Result:

- aligned

### 5. Local machine filesystem structure must not appear in public metadata

Source documents:

- `README.md` public/private boundary
- `AGENTS.md` output-rule orientation
- `CLAUDE.md` clean-room rule

Policy alignment:

- `T05.2.1` identifies absolute local paths as `S5`
- `T05.2.3` blocks them
- `T05.2.4` forces replacement across public runtime fields

Result:

- aligned

### 6. Public metadata may preserve traceability only through sanctioned abstractions

Source documents:

- `README.md` current clean-room outputs
- `AGENTS.md` output rule
- ADR guidance referenced in project docs

Policy alignment:

- `T05.2.2` explicitly permits opaque `private://...` handles
- `T05.2.4` prefers opaque handle replacement for private evidence references

Result:

- aligned

## Residual Tensions

### 1. Repo-safe relative references remain a bounded exception

Description:

- `T05.2.2` allows repo-safe relative references such as `scripts/mame_autoboot.lua`
- this is compatible with the documented guardrails, but it is narrower than a general “relative paths are okay” rule

Assessment:

- acceptable
- must remain explicitly allowlisted during implementation

### 2. Sanitized process output remains operational, not evidentiary

Description:

- `execution.stdout` and `execution.stderr` may remain after sanitization

Assessment:

- acceptable
- only if they remain path-free and do not expose private evidence, ROM placement, or local machine structure

## Alignment Conclusion

No policy artifact from `T05.2.1` through `T05.2.4` contradicts:

- the repo output rule
- the clean-room private/public boundary
- the legal guardrails against ROM, frame, crop, and raw evidence leakage

The remaining implementation-sensitive nuance is not policy contradiction but operational discipline:

- repo-safe relative references must be explicitly allowlisted
- sanitized process output must remain non-evidentiary and path-free

## Ready State For Next Step

`T05.2.5.4` can proceed without reopening output-rule interpretation.
