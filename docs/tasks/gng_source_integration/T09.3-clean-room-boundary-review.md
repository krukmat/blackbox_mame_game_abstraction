# T09.3 - Clean-room Boundary Review

## Status

✅ Done — 2026-05-13

## Files and Lines Affected

No source files modified. Read-only audit of T09.2 draft schema.

## Purpose

Audit the draft schema from T09.2 against the three clean-room rules before writing any file. Gate that prevents copyright-unsafe fields from entering the public output.

## Reference Reasoning

`Low`

Reasoning basis:

- mechanical pass/fail check against defined rules
- no implementation decisions required
- ADR-006, ADR-007, ADR-008 define the exact rules being checked

## Scope

- verify no field contains frame paths, crop paths, or ROM references
- verify no field contains character names or visual descriptions with copyright
- verify all numeric values are abstract units, not pixel measurements
- verify state and event vocabularies are game-agnostic enough to be reused

## Out of Scope

- modifying any source file
- writing the schema file (T09.4)

## Dependencies

- `T09.2`

## Blocks

- `T09.4`

## Audit Results

Audited: `docs/tasks/gng_source_integration/T09.2-schema-field-definitions.md` — `## Draft Schema` section.
ADRs applied: ADR-003, ADR-006, ADR-007, ADR-008.

---

### Rule 1 — No frame/crop path references

**Result: PASS**

Checked every field name and every enum value across all 5 categories. No field contains:
- `frames`, `crops`, `screenshots`, `video`, `states` (ADR-003 blocked directory names)
- `evidence/private/`, `/frames/`, `/crops/` (ADR-003 path markers)
- file extensions `.png`, `.jpg`, `.avi`, `.pgm`, `.sav` (ADR-003 blocked suffixes)

The `spawn_delay_frames` field uses "frames" as a unit label in the field name, not as a directory reference. This is a count of game ticks, not a path component. No risk.

---

### Rule 2 — No ROM addresses or ROM-derived constants

**Result: PASS**

No field contains a hardcoded numeric constant derived from ROM analysis. All numeric fields (`velocity_x`, `velocity_y`, `gravity_units_per_frame`, `spawn_delay_frames`, `score_delta`) are typed as `number` or `integer` with no default value other than `0` for `score_delta`.

The "Fields requiring T10 calibration" table explicitly flags `velocity_x` (projectile), `velocity_y` (jump initial), `gravity_units_per_frame`, and `spawn_delay_frames` as measurement-deferred. No ROM lookup is implied or referenced.

---

### Rule 3 — No copyright character names in field names or vocabularies

**Result: PASS**

Checked all `entity_type` enum values:

| Value | Assessment |
|-------|-----------|
| `player` | generic role label — safe |
| `enemy_a` | generic archetype — safe |
| `enemy_b` | generic archetype — safe |
| `boss_a` | generic archetype — safe |
| `projectile` | generic object type — safe |
| `hazard` | generic environmental type — safe |

No proper nouns (character names, game-specific weapon names, stage names) appear in any field name or enum value. The T09.1 exclusion note ("use `player`, `enemy_a`, etc.") is honored throughout.

`entity_id` is documented as "use role labels: player, enemy_a, enemy_b, boss_a, projectile_0, …" — no name with copyright is prescribed.

---

### Rule 4 — All numeric fields use abstract units

**Result: PASS**

| Field | Unit claim | Assessment |
|-------|-----------|-----------|
| `x`, `y` | "abstract units, not pixels" — documented in notes | safe |
| `velocity_x`, `velocity_y` | abstract units per frame — no pixel dimension implied | safe |
| `gravity_units_per_frame` | "abstract units" — name embeds the abstraction | safe |
| `spawn_delay_frames` | integer count of game frames — no pixel dimension | safe |
| `score_delta` | integer — game points, not a spatial unit | safe |
| `frame` | integer frame index — ordinal, not a pixel coord | safe |

No field implies a pixel resolution (e.g., `x_px`, `width_pixels`). The resolution 256×224 from the T09.1 video metadata does not appear anywhere in the schema.

---

### Rule 5 — State vocabulary is abstract (not entity-specific)

**Result: PASS**

All `state` enum values across all 5 categories:

| Value | Assessment |
|-------|-----------|
| `idle` | generic — safe |
| `walking_left` / `walking_right` | directional, not entity-bound — safe |
| `grounded` | physics state — safe |
| `airborne` | physics state — safe |
| `ascending` / `descending` | physics state — safe |
| `in_flight` | generic trajectory state — safe |
| `hit` | damage state — safe |
| `dead` | lifecycle state — safe |
| `despawned` | lifecycle state — safe |

No state name encodes entity identity (e.g., no `arthur_running`, no `zombie_idle`). The vocabulary is fully reusable for a different game without modification.

### Open notes for T09.4

- `spawn_delay_frames` is an extension field not present in `trace.schema.json`. T09.4 must decide whether to add it to the base schema or define it as an optional mechanic overlay.
- `gravity_units_per_frame` is similarly mechanic-specific. Same decision needed.
- Both extension fields must still pass through `ensure_no_private_paths` if embedded in a JSON payload — they are numeric so this is trivially satisfied, but the check should be documented in T09.4.
