# T05.1 - Redaction Boundary Audit

## Status

Completed

## Purpose

Identify the concrete public metadata surfaces where local paths, ROM locations, or private evidence details can leak before the unified redaction policy is defined.

## Public Output Surfaces Audited

### 1. `apps/mame-harness/cli.py::handle_run`

Public metadata fields currently written to `specs/run_metadata.json`:

- `run_id`
- `game_shortname`
- `input_plan`
- `frame_plan_length`
- `dry_run`
- `private_evidence_ref`
- `state`
- `notes`
- `runner_status`
- `command`
- `preflight`
- `execution`

Primary leakage risk:

- `command` may contain `rom_path`, absolute local paths, and non-private machine paths
- `preflight.issues[*].message` may include resolved ROM or binary paths
- `execution.stdout` and `execution.stderr` may include machine-local paths emitted by MAME or wrapper commands

### 2. `apps/mame-harness/cli.py::_redact_command_paths`

Current behavior:

- rewrites `evidence/private/...` command arguments into `private://...`

Current gaps:

- does not sanitize `rom_path`
- does not sanitize unrelated absolute local paths
- does not sanitize workspace-relative paths outside `evidence/private`
- only operates on `command`, not on `preflight` or `execution`

### 3. `apps/mame-harness/metadata_writer.py::write_public_metadata`

Current behavior:

- converts dataclasses and `Path` values to JSON-safe data
- rejects payloads that still contain blocked private path markers through `ensure_no_private_paths`

Current gaps:

- no explicit rejection for absolute local paths
- no explicit rejection for ROM paths unless they also trip a blocked suffix or marker
- depends on upstream sanitization for many path-shaped strings

### 4. `apps/mame-harness/guardrails.py::ensure_no_private_paths`

Current behavior:

- blocks strings containing:
  - `evidence/private/`
  - `/frames/`
  - `/crops/`

Current gaps:

- does not block absolute local paths such as `/Users/...`
- does not block direct ROM paths such as `/roms/gng.zip`
- does not block non-frame private subpaths unless they include the exact blocked markers
- does not treat Windows absolute paths explicitly

### 5. Existing Public Artifact Shape

Observed sample in `specs/run_metadata.json`:

- `private_evidence_ref` already uses opaque `private://...` handles
- `command` already redacts evidence-private directories
- public metadata currently contains `scripts/mame_autoboot.lua`, which is repo-relative and currently treated as acceptable

## Leakage Classes Identified

The audit identified these path/value classes as relevant for `T05`:

1. private evidence paths under `evidence/private/...`
2. frame paths
3. crop paths
4. direct ROM paths including `gng.zip`
5. absolute local machine paths
6. non-private workspace paths appearing inside public command or error payloads
7. unsanitized process output in `execution.stdout` and `execution.stderr`
8. unsanitized human-readable validation errors in `preflight.issues[*].message`

## Fields Requiring Policy Coverage In `T05.2`

- `command[*]`
- `preflight.issues[*].message`
- `execution.stdout`
- `execution.stderr`
- any future string field written by `handle_run`
- any public metadata payload written through `write_public_metadata`

## Audit Conclusion

The highest-risk current public surface is not the file writer itself. It is the combination of:

- partial command-only redaction in `cli.py`
- permissive string acceptance in `ensure_no_private_paths`
- structured runner fields (`preflight`, `execution`) that can carry path-bearing strings into public metadata

`T05.2` must therefore define one policy that covers command arguments, structured error messages, and process output together.
