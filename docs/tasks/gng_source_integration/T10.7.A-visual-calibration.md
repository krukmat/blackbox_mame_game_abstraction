## Objective

Compute physically consistent `jumpVelocity_y` and `gravity_y` constants from a controlled, jump-only MAME capture where the user visually confirms **both the peak frame and the land frame** for each jump. The land frame enables an independent gravity estimate from the descent half of each arc, providing free cross-validation. Anchors calibration on ≥ 5 **valid** confirmed jumps (passing flat-ground + symmetry checks) so the resulting constants pass the back-check `|t_peak_predicted − t_peak_observed| / t_peak_observed < 0.30`.

#### ST.A3a — Implement `visual_jump_picker.py`

**Owner: Agent**

**Governing ADR**: [ADR-019 — Human-Validated Calibration Candidates Pattern](../../adr/ADR-019-human-validated-calibration-candidates.md). The picker must conform to ADR-019's contract: reads only public artifacts, outputs frame numbers + numeric metadata only to stdout (no private paths), writes structured candidate JSON to `evidence/private/run_<id>/logs/<picker_name>_candidates.json`, uses explicit source-visible algorithm parameters.

Create `apps/mame-harness/visual_jump_picker.py` with this contract:

- **Input**: `run_id` (CLI positional argument)
- **Reads**: `specs/traces/gng_trace.json` (assumes ST.A2 already regenerated it)
- **Algorithm**:
  1. Filter `entity_id == "player"` entries → `(frame, y)` time series
  2. Custom numpy peak finder on `−y` (valleys in screen-y space = peaks in altitude):
     - Local minimum: `y[i] < y[i-1] and y[i] <= y[i+1]`
     - Filter: drop minima within `min_distance = 30` of a previously-accepted minimum (keep the deeper one)
     - Filter: drop minima where `(local_max in window − y[i]) < min_prominence = 0.05`
  3. For each surviving peak frame `P`:
     - `jump_start_frame` = last frame in `[P − 25, P − 3]` where Arthur's y is stable (within 0.01 of `median(y[P-30:P-25])`)
     - `land_frame` = first frame in `[P + 3, P + 25]` where Arthur's y is stable (within 0.01 of `median(y[P+25:P+30])`)
     - If either anchor cannot be determined, skip the candidate
  4. Compute per-candidate metrics:
     - `height_ascend = y_ground − y_peak`
     - `height_descend = y_land − y_peak`
     - `t_ascend = peak_frame − jump_start_frame`
     - `t_descend = land_frame − peak_frame`
     - `flat_ok = |y_land − y_ground| < 0.02`
     - `sym_ok = 0.7 ≤ (gravity_descend / gravity_ascend) ≤ 1.4` (where each gravity = 2·h/t²)
- **Outputs**:
  1. Stdout: human-readable table with columns: `id | jump_start | peak | land | height_ascend | t_ascend | t_descend | flat_ok | sym_ok`
  2. Side effect: write `evidence/private/run_<id>/logs/jump_candidates.json` (private artifact; consumed by ST.A4)
- **Path discipline**: tool output must contain only frame numbers and numeric metadata. No private file paths printed to stdout. User is told the path convention once at the top of output: "Open `evidence/private/run_<id>/frames/extracted_png/<NNNN>.png` to inspect any peak frame."

**Validation**: `python visual_jump_picker.py t10_7_jumps` runs without error; outputs ≥ 1 candidate from the current capture.

### ST.A4 — Compute per-jump physics (with ascent + descent gravity cross-check)

**Owner: Agent**

1. For each confirmed `(jump_start_frame, peak_frame, land_frame)`:
   - Look up:
     - `y_ground` = trace y-value at `jump_start_frame` (fallback ± 1 frame if missing)
     - `y_peak` = trace y-value at `peak_frame` (fallback ± 1 frame if missing)
     - `y_land` = trace y-value at `land_frame` (fallback ± 1 frame if missing)
   - Compute:
     - `height_ascend = y_ground − y_peak`  (must be > 0.01; else drop)
     - `height_descend = y_land − y_peak`  (must be > 0.01; else drop)
     - `t_ascend = peak_frame − jump_start_frame`
     - `t_descend = land_frame − peak_frame`
     - `jumpVelocity_y_per_frame = 2 × height_ascend / t_ascend`  (from ascent only)
     - `gravity_ascend = 2 × height_ascend / (t_ascend)²`
     - `gravity_descend = 2 × height_descend / (t_descend)²`

2. **Per-jump validation gates** (drop the jump if any fails):
   - **Flat-ground check**: `|y_land − y_ground| < 0.02`. Mark `flat_ok` per jump.
   - **Symmetry check**: `0.7 ≤ gravity_descend / gravity_ascend ≤ 1.4`. Mark `sym_ok` per jump.
   - Drop the jump from the median pool if `not (flat_ok and sym_ok)`.

3. For each valid jump, combine:
   - `gravity_combined = (gravity_ascend + gravity_descend) / 2`

4. Aggregate across valid jumps:
   - `jumpVelocity_y_per_frame_median = median(jumpVelocity_y across valid jumps)`
   - `gravity_per_frame_sq_median = median(gravity_combined across valid jumps)`
   - `sample_count = N_valid`

5. Convert to per-second:
   - `jumpVelocity_y_per_second = jumpVelocity_y_per_frame_median × 60`
   - `gravity_per_second_sq = gravity_per_frame_sq_median × 3600`

6. Report to user before writing to YAML:
   - Per-jump table: `(jump#, t_ascend, t_descend, height_ascend, height_descend, v0, g_ascend, g_descend, flat_ok, sym_ok)`
   - Aggregated medians + sample count
   - Rejected jumps with reason
   - Back-check: `t_peak_predicted = jumpVelocity_y_per_frame_median / gravity_per_frame_sq_median` vs median observed `t_ascend`

**Validation:** Reported values are positive; back-check is within ± 30%; ≥ 5 valid jumps.

## Risks

- **R1 — User picks non-peak / non-land frame**: Mitigation: candidate windows are wide (20+ frames); user compares adjacent frames visually. Symmetry check (ST.A4 step 2) catches misidentification because asymmetric arcs are rejected.
- **R2 — Insufficient valid jumps**: If user records < 5 jumps that pass both validation gates, repeat ST.A1 in a second session. Aim for 8–10 recorded jumps to comfortably reach 5+ valid after rejections.
- **R3 — Trace lacks player entry at confirmed frame**: Fall back to nearest ± 1 frame; if still missing, drop that jump and use remaining samples.
- **R4 — Jump-button mapping detection fails**: Mitigation: agent inspects raw `input_plan.json` and identifies whichever non-empty button-list correlates with subsequent ascending states in trace.
- **R5 — Variable y_ground across jumps (stairs/platforms)**: Mitigation: reject jumps where `|y_land − y_ground| > 0.02` (about 4 pixels).
- **R6 — Asymmetric arc (descent gravity disagrees with ascent)**: Mitigation: reject jumps where `gravity_descend / gravity_ascend` is outside `[0.7, 1.4]`. Likely causes: input lag, frame skip, partial occlusion at peak, animation pose with offset bounding box.
