## Purpose

Implement the first two functions of the `TraceEntry` production pipeline: computing abstract velocity from consecutive `FrameDiffStat` center positions, and assigning the canonical `state` string from velocity values using the contract defined in T10.2.2.1.

## Reference Reasoning

`Medium`

Reasoning basis:

- implementation follows from the contract in T10.2.2.1 — no new design decisions
- edge cases require care: first frame (no previous stat), zero-motion frames, and sign conventions for velocity_y (negative = ascending per T09.2)
- test fixtures must cover all velocity/state combinations from the T09.2 vocabulary

## Scope

- TDD: write `test_trace_extractor.py` with test cases covering all state enum values before writing source
- implement `_compute_velocity(prev: FrameDiffStat | None, curr: FrameDiffStat) -> tuple[float, float]`
- implement `_assign_state(vx: float, vy: float, prev_state: str) -> str`
- velocity_y sign convention: negative = ascending (upward), positive = descending, matches T09.2
- thresholds from the contract in T10.2.2.1; no pixel values in threshold definitions

## Out of Scope

- event inference (T10.2.2.3)
- assembling full TraceEntry records (T10.2.2.4)

## Dependencies

- T10.2.2.1

## Blocks

## Acceptance Criteria

- `_compute_velocity` returns `(0.0, 0.0)` when `prev` is None (first frame)
- `_assign_state` returns only values from T09.2 `state.enum`
- tests cover: idle, walking_left, walking_right, grounded, airborne, ascending, descending
- all new tests pass; existing 118+ tests unchanged
