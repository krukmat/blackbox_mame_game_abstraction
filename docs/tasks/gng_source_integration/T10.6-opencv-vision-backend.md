## Purpose

The current `FrameDiffer` produces low-quality traces with three structural problems:

| Problem | Current metric | Root cause |
|---------|---------------|------------|
| Player miss rate | ~76% (769/3162 frames) | Consecutive-frame diff has zero signal when Arthur is stationary |
| HUD noise | 144k hazard entries (87% of trace) | Bottom 20px of frame (score/lives HUD) is never masked |
| Player spawn/die cascade | 111 spawn events instead of 1 | Missing frames trigger die → next detection triggers spawn |

T10.6 addresses all three by introducing OpenCV as a replaceable backend for the vision layer, keeping the pure-Python path for unit tests.

## Architectural Decision

This task introduces ADR-013 (OpenCV as Replaceable Vision Backend). Read that ADR before touching any module in this task.

## T10.6-B — HUD ROI Masking

### Status
✅ Done

### Purpose
Exclude the GNG HUD (bottom 20 rows of the 256×224 frame) from diff computation. This eliminates the 144k spurious `hazard` entries in the trace by ensuring no diff blobs are generated from score/lives/timer changes.

### Scope
- In `GNGVisionConfig`: `hud_y_top: int = 204` is the first row of the HUD. All rows `y >= hud_y_top` are excluded.
- `PurePythonBackend.find_regions` applies the mask before the BFS: skip any `(x, y)` point where `y >= config.hud_y_top`.
- The config is passed to the backend at construction: `PurePythonBackend(config: GNGVisionConfig)`.
- TDD first — write `test_hud_mask_excludes_bottom_rows` before implementation:
  - A frame pair where only pixels in rows 204–223 differ → `changed_regions == []`.
  - A frame pair where pixels differ in row 100 AND row 210 → only row 100 region returned.

- Background subtraction (T10.6-D).
- The `hud_y_top` value is hardcoded for GNG 256×224. A game at a different resolution requires a different `GNGVisionConfig` instance — not handled here.

### Dependencies

### Reasoning Grade
`Low` — index arithmetic, no algorithmic complexity.

### Effort Grade

### Recommended Model

## T10.6-C — cv2.connectedComponentsWithStats Contour Extraction

### Status
✅ Done

### Purpose
Implement `OpenCVBackend` that uses `cv2.connectedComponentsWithStats` to produce `MotionBox` regions from a grayscale diff mask. Replaces the Python BFS flood fill for production runs.

### Scope
- New class `OpenCVBackend(config: GNGVisionConfig)` in `packages/vision/frame_differ.py`.
- `find_regions` implementation:
  ```
  1. Convert prev_pixels and curr_pixels to numpy uint8 arrays.
  2. diff_mask = np.abs(prev_arr - curr_arr) > config.diff_threshold
  3. Apply HUD mask: diff_mask[config.hud_y_top:, :] = False
  4. diff_mask_u8 = diff_mask.astype(np.uint8) * 255
  5. num_labels, labels, stats, centroids = cv2.connectedComponentsWithStats(diff_mask_u8)
  6. For each label > 0 (label 0 = background):
       area = stats[label, cv2.CC_STAT_AREA]
       if area < config.min_contour_area: skip
       x = stats[label, cv2.CC_STAT_LEFT]
       y = stats[label, cv2.CC_STAT_TOP]
       w = stats[label, cv2.CC_STAT_WIDTH]
       h = stats[label, cv2.CC_STAT_HEIGHT]
       cx, cy = centroids[label]
       yield MotionBox(x, y, w, h, cx, cy)
  7. Sort by area descending (same as current).
  ```
- Return `(changed_pixel_ratio, list[MotionBox])` — identical output type.
- `vision_pipeline.py` constructs `FrameDiffer(backend=OpenCVBackend(GNGVisionConfig()))`.
- TDD: `test_frame_differ_opencv.py` — same acceptance criteria as `test_frame_differ_multi.py`:
  - Two separated blobs → two regions.
  - Minimum area filter (< 4 px rejected, ≥ 4 px kept).
  - Single blob → single region.
  - No-change frame → empty regions.
  - HUD-only changes → empty regions.

### Out of Scope
- Background subtraction (T10.6-D) — this task still uses consecutive diff.
- `PurePythonBackend` changes.

### Dependencies
- T10.6-A (OpenCV installed, FrameDifferBackend protocol).
- T10.6-B (HUD mask config, mask applied in find_regions).

### Reasoning Grade
`Medium` — requires correct numpy/cv2 data type handling; edge cases (all-black frame, single-pixel diff) must be verified against cv2 output format.

### Effort Grade
`M`

### Recommended Model
`Sonnet`

### Acceptance Criteria
- All acceptance criteria from `test_frame_differ_multi.py` pass when run against `OpenCVBackend`.
- HUD mask eliminates HUD-zone blobs.

## T10.6-D — MOG2 Background Subtraction

### Status
✅ Done

### Purpose
Replace the consecutive-frame diff mask with a MOG2 foreground mask in `OpenCVBackend`. This detects entities that are stationary across multiple frames, addressing the root cause of the 76% player miss rate.

### Scope
- `OpenCVBackend` gains a two-phase `diff_manifest` method:
  ```
  Phase 1 — Warm-up (frames 0..49):
    Feed each frame to mog2.apply(frame) without returning results (model building only).
    Fall back to consecutive diff for these frames.

  Phase 2 — Inference (frames 50+):
    foreground_mask = mog2.apply(curr_frame)
    Apply HUD mask: foreground_mask[config.hud_y_top:, :] = 0
    Run cv2.connectedComponentsWithStats on foreground_mask
    → MotionBox list as in T10.6-C
  ```
- MOG2 parameters: `history=300, varThreshold=16, detectShadows=False`.
- These are set in `GNGVisionConfig`:
  ```python
  mog2_history: int = 300
  mog2_var_threshold: float = 16.0
  mog2_warmup_frames: int = 50
  ```
- `FrameDiffer.diff_manifest` calls the backend's `diff_manifest(manifest)` for the full sequence (not `find_regions` per frame), so the backend can maintain state across frames.
- `PurePythonBackend.diff_manifest` — implements the existing consecutive-diff loop (no change).
- Update `FrameDifferBackend` protocol:
  ```python
  class FrameDifferBackend(Protocol):
      def diff_manifest(self, manifest: FrameManifest) -> list[FrameDiffStat]: ...
  ```
  Remove the per-frame `find_regions` method from the protocol (backends handle their own loop).
- TDD:
  - `test_mog2_detects_stationary_entity`: three identical frames except entity is present in same position all three → entity detected in frame 3 foreground mask.
  - `test_mog2_warmup_frames_use_diff_fallback`: first 50 frames use consecutive diff (no crash, returns results).

### Out of Scope
- MOG2 reset on camera scroll (Known Gap per ADR-013 — stage 2+ only).
- Optical flow / cross-frame entity ID continuity (separate task if ever needed).

### Dependencies
- T10.6-C (OpenCVBackend contour extraction working on consecutive diff first).

### Reasoning Grade
`High` — MOG2 state management across a frame sequence; warm-up period edge cases; protocol change affects both backends; stationary-entity detection requires careful test fixture construction (synthetic pixel sequences).

### Effort Grade
`M`

### Recommended Model
`Sonnet`

### Acceptance Criteria
- Stationary entity (same pixel values across frames) is detected in the foreground mask after warm-up.
- First 50 frames fall back to consecutive diff without crash.
- HUD mask is applied to the MOG2 foreground mask.
- All 282+ tests pass.
- `PurePythonBackend.diff_manifest` satisfies the updated protocol.

## T10.6-E — Player Gap Tolerance

### Status
🔲 Planned

### Purpose
Suppress false `die`/`spawn` events caused by short gaps in player detection (quiet frames, brief occlusion). Instead of emitting `die` immediately when the player is absent, hold for up to `player_gap_tolerance` consecutive frames before concluding the player has left.

### Scope
- `GNGVisionConfig.player_gap_tolerance: int = 3` — configurable, defaulting to 3 frames.
- In `extract_trace`, introduce `player_gap_counter: int = 0`:
  - When `find_arthur` returns `None`: increment `player_gap_counter`.
    - If `player_gap_counter <= player_gap_tolerance`: do NOT emit `die`, do NOT remove from `prev_seen_by_id`. Carry forward last known `prev_region` for velocity computation.
    - If `player_gap_counter > player_gap_tolerance`: emit `die` on last real entry, remove from `prev_seen_by_id`, reset counter.
  - When `find_arthur` returns a match: reset `player_gap_counter = 0`.
- Gap tolerance applies only to `entity_id == "player"`. Ephemeral enemies (`enemy_a_{frame}`) retain immediate die behavior.
- TDD first — `packages/vision/tests/test_gap_tolerance.py`:
  - Player absent for 1 frame → no `die`.
  - Player absent for 3 frames → no `die`.
  - Player absent for 4 frames → `die` on last real entry.
  - Player returns after 2 absent frames → no `die`, no new `spawn`.
  - Enemy absent for 1 frame → `die` immediately (gap tolerance does not apply).

### Out of Scope
- Gap tolerance for enemies or projectiles.
- Position interpolation during gap (last known position is held, velocity = 0).

### Dependencies
- T10.6-D (MOG2 improves detection so fewer gaps remain; gap tolerance handles the remainder).

### Reasoning Grade
`Medium` — interaction between gap counter, `prev_seen_by_id`, and die mutation must be correct and idempotent; TDD covers all counter boundary cases.

### Effort Grade
`S`

### Recommended Model
`Sonnet`

### Acceptance Criteria
- Player absent ≤ `player_gap_tolerance` frames → no `die` event.
- Player absent > `player_gap_tolerance` frames → `die` on last real entry.
- Player reappears after short gap → no new `spawn`.
- Enemy absence still triggers immediate `die`.
- All 282+ tests pass.
- `player_gap_counter` logic is covered by dedicated tests.
