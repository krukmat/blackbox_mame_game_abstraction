# T05.2.5.2 - Surface Consistency Review

## Status

Completed

## Purpose

Verify that `command`, `preflight`, and `execution` apply consistent handling to the same sensitive classes, with any differences justified by field type rather than by ad hoc policy drift.

## Surfaces Reviewed

- `command[*]`
- `preflight.issues[*].message`
- `execution.stdout`
- `execution.stderr`

## Consistent Rules Found

### 1. Sensitive filesystem-bearing values never remain verbatim across any reviewed surface

Applies to:

- `S1 Private evidence path`
- `S2 Frame path`
- `S4 Direct ROM path`
- `S5 Absolute local machine path`

Consistency result:

- `command[*]` uses `replace`
- `preflight.issues[*].message` uses `replace`
- `execution.stdout` uses `replace`
- `execution.stderr` uses `replace`

Assessment:

- consistent
- differences are only in replacement style, not in boundary rule

### 2. Human-readable surfaces consistently require path-free retained meaning

Applies to:

- `preflight.issues[*].message`
- `execution.stdout`
- `execution.stderr`

Consistency result:

- all three surfaces allow meaning to remain only after path sanitization

Assessment:

- consistent
- these are message-bearing fields, so replacement into path-free wording is the expected common rule

### 3. `command[*]` is the only reviewed surface allowed to preserve repo-safe relative references

Applies to:

- `S6 Non-private workspace path in public runtime payload`

Consistency result:

- `command[*]`: `allow or replace`
- `preflight.issues[*].message`: `replace`
- `execution.stdout`: `replace`
- `execution.stderr`: `replace`

Assessment:

- consistent
- the difference is justified by field type

Why justified:

- `command[*]` is a structured argument list where a repo-safe helper path can remain meaningful and bounded
- `preflight` and `execution` are free-form human-readable surfaces and should not preserve raw workspace path strings

### 4. Crop-path handling is intentionally stricter in `command[*]` than in message-bearing surfaces

Applies to:

- `S3 Crop path`

Consistency result:

- `command[*]`: `block`
- `preflight.issues[*].message`: `replace`
- `execution.stdout`: `replace`
- `execution.stderr`: `replace`

Assessment:

- consistent
- difference is justified by field type and expected runtime behavior

Why justified:

- crop paths should never be present as structured runtime command arguments
- if they appear in human-readable text, the policy still permits keeping the operational meaning after sanitization

## Surface-Specific Justifications

### `command[*]`

This surface is:

- structured
- tokenized
- intentionally public as a redacted execution description

Therefore it may preserve:

- abstract arguments
- non-path scalars
- opaque `private://...` handles
- explicitly repo-safe helper references

It may not preserve:

- raw local paths
- ROM paths
- non-approved workspace paths

### `preflight.issues[*].message`

This surface is:

- explanatory
- human-readable
- not intended to preserve raw path tokens

Therefore it should preserve only:

- path-free explanations
- opaque handles if needed

### `execution.stdout` and `execution.stderr`

These surfaces are:

- free-form process output
- the least predictable string sources in the public payload

Therefore they should preserve only:

- path-free retained meaning
- no raw local, ROM, frame, crop, or workspace path strings

## No Operational Contradictions Found

No contradiction was found where:

- one surface allows a sensitive class verbatim while another blocks the same verbatim form without field-type justification

The only material differences are:

- `S6` in `command[*]`
- `S3` in `command[*]`

Both differences are justified by the structured nature of `command[*]` versus the message-bearing nature of `preflight` and `execution`.

## Review Conclusion

The reviewed surfaces are operationally consistent with the redaction decision table.

`T05.3` can implement:

- element-wise sanitization for `command[*]`
- message/text sanitization for `preflight.issues[*].message`
- free-form output sanitization for `execution.stdout` and `execution.stderr`

without redefining cross-surface policy.
