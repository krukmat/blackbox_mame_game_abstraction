# T10.9.4 — EntityTracker Integration + Regression Tests

## Status

🔲 Planned — awaiting parent-task approval.

## Parent Task

[T10.9 — Boss and Devil Tracking](./T10.9-boss-and-devil-tracking.md)

## Objective

Load the new `enemy_c` (Red Arremer) and `boss_a` (cyclops) signatures into the runtime `EntityTracker` instance inside `extract_trace`, and add regression tests covering the new entity types and pipeline interactions with the scroll detector.

## Scope

- Update `packages/vision/trace_extractor.py` (or the signature-loader module it consumes) to include `enemy_c` and `boss_a` signature entries from `specs/calibration/gng_enemy_signatures.yaml`.
- Confirm `EntityTracker` greedy-assignment ordering by `spawn_frame` produces sensible behavior when Arthur, Arremer, and boss coexist on screen (rare but possible during the boss approach).
- Add `packages/vision/tests/test_boss_devil_tracking.py` with scenarios:
  - **B1 — Single Arremer perched then flying**: perched for 10 frames at low `velocity_y`, then swoops at high `max_frame_jump_px`; same `entity_id` persists.
  - **B2 — Two cyclopes simultaneous**: two `boss_a` entities track independently with distinct `entity_id` values.
  - **B3 — Cyclops appears after MOG2 warmup**: scroll event closes, warmup completes, cyclops appears; `entity_id` allocated cleanly without spurious early spawn.
  - **B4 — Arremer near Arthur signature overlap**: Arremer at `center_y` close to Arthur's bound; Arthur keeps `entity_id="player"`, Arremer gets `enemy_c_...`.
  - **B5 — Cyclops merge then split**: two cyclopes briefly overlap into one FrameDiffer region for ≤ `gap_tolerance_frames`, then re-separate; both `entity_id` values resume.
- Ensure all T10.8 regression tests continue to pass with the extended signature set.

## Out of Scope

- Trace regeneration (T10.9.5).
- Documentation/ADR updates (T10.9.5).
- Performance benchmarking.
- Modifying the `EntityTracker` algorithm itself.

## Dependencies

- ✅ T10.9.2 — Red Arremer signature in YAML.
- ✅ T10.9.3 — cyclops signature in YAML.

## Acceptance Criteria

1. `extract_trace` consumes `enemy_c` and `boss_a` signatures from the YAML and instantiates them in the `EntityTracker`.
2. `packages/vision/tests/test_boss_devil_tracking.py` exists with all five scenarios (B1–B5) implemented and passing.
3. All T10.8 regression tests (`test_enemy_tracking_integration.py`, `test_trace_extractor_enemies.py`) continue to pass.
4. `test_pipeline_scroll_integration.py` (from T10.9.1) extended to assert no `boss_a`/`enemy_c` spawn during the warmup window.
5. Full `pytest packages/vision/tests/` passes.
6. Full `pytest apps/mame-harness/tests/` passes.
7. No existing test is deleted, skipped, or weakened to accommodate new behavior.
