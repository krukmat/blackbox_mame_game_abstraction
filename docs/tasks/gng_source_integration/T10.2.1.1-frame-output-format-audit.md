## Purpose

Determine the exact private evidence layout produced by the calibrated T10.1 gameplay capture so that T10.2.1.2 can extend `FrameManifest.from_run` correctly. The current implementation does `glob("*.pgm")`, but T10.1.3 documented that real gameplay evidence lives in `video/capture.avi` and that `frames/` contains only a startup PNG snapshot.

## Objective

Produce a read-only evidence audit and one explicit format decision for T10.2.1.2: what private artifact becomes the canonical frame input to the vision layer.

## Scope

- inspect the latest calibrated gameplay run under `evidence/private/run_<id>/`
- record actual evidence sources present under `frames/`, `video/`, `logs/`, and `states/`
- inspect `video/capture.avi` enough to record container, codec, resolution, frame count, and naming plan for extracted frames
- decide whether T10.2.1.2 should:
  - read extracted PNG frames from a private derived directory, or
  - introduce another private intermediate format
- document findings under `## Audit Findings` in this file

## Out of Scope

- modifying `packages/vision/` code
- introducing a new dependency
- public trace generation

## Dependencies

- T10.1.3

## Blocks

## Audit Findings

### Run Used

- `run_id`: `c935b5ea9321`

### Evidence Layout Observed

- `frames/`: contains only `frames/gngb/0000.png` (single 256x224 PNG startup snapshot). There is no per-frame gameplay image sequence here.
- `video/`: contains the full gameplay capture in `capture.avi`, plus derived inspection artifacts: `capture.mp4`, `key_001.png` through `key_007.png`, and `thumb_001.png` through `thumb_012.png`.
- `logs/`: directory exists but is empty.
- `states/`: directory exists but is empty.

### AVI Summary

- container: `avi`
- codec: `rawvideo` (`bgr24`)
- resolution: `256x224`
- frame count: `359`
- note: duration is `6.019712s` at approximately `59.64 fps`
- content validity note: manual review of the derived video indicates this run does not yet show usable in-game Arthur movement; it is a format-valid capture artifact, but not yet a behavior-valid gameplay sample

### Why `frames/` Is Not the Canonical Gameplay Source

- `frames/` does not contain a real gameplay sequence. It contains one startup snapshot only (`0000.png`).
- T10.2 needs consecutive frames for motion differencing and trace extraction. A single image cannot support `FrameDiffer` or per-frame behavioral extraction.
- The multi-frame evidence actually produced by the calibrated run is `video/capture.avi` with 359 frames.
- The extra PNGs currently under `video/` are not a canonical source either: they are sparse preview artifacts, not a full deterministic frame series.
- `capture.mp4` is also not the canonical source: it is a derived transcode, not the original raw capture artifact emitted by the run.

### Decision

- Canonical private gameplay evidence for T10.2: `video/capture.avi`
- Private extracted-frame directory layout: materialize a private derived sequence under `frames/extracted_png/` using zero-based, zero-padded names:
  - `frames/extracted_png/0000.png`
  - `frames/extracted_png/0001.png`
  - `...`
  - `frames/extracted_png/0358.png`
- Extraction mechanism to use in T10.2.1.2: use `ffmpeg` to expand the canonical AVI into a deterministic full-frame PNG sequence, preserving every frame:
  - `ffmpeg -i video/capture.avi -vsync 0 -start_number 0 frames/extracted_png/%04d.png`
- Extension `FrameManifest` must support next: `.png`
- Scope boundary: this task resolves the canonical input format and extraction layout only. It does not certify that the current run contains sufficient gameplay content for downstream behavioral extraction.

### Strategy for T10.2.1.2

- Keep `video/capture.avi` as the source of truth for real gameplay evidence.
- Treat `frames/extracted_png/` as a private, reproducible materialization layer for the vision pipeline.
- Extend `FrameManifest` to load the extracted PNG sequence after validating every file path with the existing private-evidence guardrail.
- Preserve existing `.pgm` support for tests and placeholders; add `.png` support for real-capture runs rather than replacing PGM behavior.
- If a later task confirms that `run_c935b5ea9321` is boot/attract only, T10.2.1.2 should still target the same extraction layout, but the actual behavioral extraction run must use a recaptured evidence session with valid gameplay content.
