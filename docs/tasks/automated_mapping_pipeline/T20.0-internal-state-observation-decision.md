# T20.0 — Internal-State Observation Clean-Room Decision (ADR-026)

## Objective
Decide, and record as an ADR, whether the framework may read MAME RAM (internal machine
state) via the Lua bridge as a measurement source, using community cheat-database addresses
that are not derived from the ROM. This is a decision gate, not an implementation.

## Scope
- Author `docs/adr/ADR-026-internal-state-observation-boundary.md` with status **Proposed**.
- State the clean-room argument both ways: (a) RAM values are numeric behavior facts, never
  expressive content, and never published, so they respect the "only abstract numbers cross"
  rule; (b) reading internal state "enters the box" and may weaken the "observable behavior
  like a player sees" theory.
- Define the contract IF accepted: addresses come only from community cheat DBs (cited, not
  ROM-disassembled); raw addresses/values stay private; only derived abstract numbers reach
  public artifacts; guardrails apply unchanged.
- Require an explicit approver decision recorded as Accepted or Rejected in the ADR.

## Out of scope
- Any memory-tap implementation (that is T20.5, gated by this decision).
- Choosing specific GNG addresses.

## Dependencies
None. This task gates T20.5 and T20.6.

## Reasoning grade
High — boundary-sensitive, legal/clean-room judgment.

## Effort grade
Low — one ADR + decision, no code.

## Recommended model
Opus.

## Acceptance criteria
- ADR-026 exists with Context, Decision (with explicit Accepted/Rejected), Consequences,
  Alternatives, Related.
- ADR Index updated in `CLAUDE.md` and `AGENTS.md`; Obsidian note added; vault indices updated.
- If Rejected: plan tasks T20.5/T20.6 are marked dropped in the plan doc.
- If Accepted: the private-only address/value contract is unambiguous enough for T20.5.
