# T20.1 — Per-Frame Input-State Logger (ADR-023)

## Objective
Capture the *actual* per-frame input state from the Lua bridge — including human keyboard
input during manual play — into a private `input_timeline.json`, establishing ground truth
for player-driven events.

## Scope
- Extend `scripts/mame_autoboot.lua` to read the resolved ioport field states each frame
  (the same fields it already injects: left/right/up/down/button1/button2/coin/start) and
  record the *effective* state (injected OR human-pressed) per frame.
- Write a private artifact `evidence/private/run_<id>/logs/input_timeline.json`:
  `[{ "frame": N, "buttons": ["right","button2"] }, ...]`.
- Read field state via the field API (e.g. `field:read()` / port read), not by re-reading the
  input plan, so manual play is captured truthfully.
- Author `docs/adr/ADR-023-ground-truth-input-timeline.md`: ground-truth input timeline is the
  authoritative source for input-driven events; CV inference is a fallback.

## Out of scope
- Changing how `trace_extractor` consumes events (that is T20.2).
- Any non-input state (positions, RAM).

## Dependencies
None (builds on existing Lua frame notifier).

## Reasoning grade
Medium — Lua API correctness, must capture human input not just injected plan.

## Effort grade
Medium.

## Acceptance criteria
- Manual capture produces `input_timeline.json` reflecting real key presses frame-accurately.
- Scripted capture's timeline matches the injected plan exactly (determinism check).
- Stdout emits no private paths; artifact lives under `evidence/private/` (gitignored).
- ADR-023 authored; ADR indices + Obsidian vault updated.
- Tests: timeline schema validity; injected-plan == timeline for a scripted run.
