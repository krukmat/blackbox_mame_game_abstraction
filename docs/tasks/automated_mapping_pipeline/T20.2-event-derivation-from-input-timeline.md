# T20.2 — Event Derivation From Input Timeline

## Objective
Make `trace_extractor` derive input-driven events (`movement_start/stop`, `jump_start`,
`fire`) from the ground-truth `input_timeline.json` (T20.1), demoting CV velocity-threshold
inference to a fallback for frames lacking an input record.

## Scope
- Load `input_timeline.json` in the trace assembly path; key by frame number.
- Replace `_infer_events` input-driven logic with edge detection on the timeline
  (button press edge → `jump_start`/`fire`; directional press/release → `movement_*`).
- Keep CV-derived states (positions/velocities) unchanged for now; only events switch source.
- Retain CV inference strictly as a fallback when no timeline is present (back-compat).

## Out of scope
- Physics constant calibration (T20.4).
- Positional/identity vision changes (T20.7/T20.8).

## Dependencies
T20.1.

## Reasoning grade
Medium — contract alignment with canonical vocabulary (ADR-008); must avoid double-emitting
events from both sources.

## Effort grade
Medium.

## Acceptance criteria
- For a scripted run, events match the injected plan exactly (no spurious `jump_start`).
- For a manual run, events reflect real presses; no dependence on velocity thresholds.
- Canonical state/event vocabulary preserved (no ADR-008 drift).
- Fallback path still works when `input_timeline.json` is absent.
- Regression tests cover: timeline-present, timeline-absent, edge detection correctness.

## Recommended model
Sonnet.
