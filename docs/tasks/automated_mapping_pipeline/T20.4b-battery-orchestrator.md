# T20.4b — Battery Orchestrator + Fail-Fast Validation + Robust Windows

## Objective
Make operator participation in calibration **minimal and retry-free**: one command runs the
whole experiment battery end-to-end and returns a single verdict table, validating each
capture immediately and telling the operator exactly which experiment (if any) to re-run and
why — never a blind retry.

## Scope
- A `calibrate-battery` orchestration command that, for each experiment plan in the battery:
  1. obtains a capture — either by launching the scripted run via the existing `run` path
     (no human play needed; battery plans are fully scripted) or by consuming an existing
     `run_id`;
  2. extracts the trace (`vision_pipeline.extract_run_trace`);
  3. runs `experiment_calibrator` on the experiment;
  4. records the result.
- **Fail-fast, specific validation** per experiment (no silent bad constants, no blind retry):
  - boot reached the controllable frame (input_timeline shows coin/start and frames reach the
    measurement window);
  - the isolated entity is present in the measurement window (trace has player/projectile
    entries there);
  - fit quality r² ≥ threshold.
  Each failure yields an actionable message: which experiment, which check failed, suggested
  fix (e.g., "re-run `gng_exp_jump_in_place`: only 1 airborne frame in window — jump not
  detected").
- **Robust window auto-detection**: within the declared `measurement_window`, auto-detect the
  stable sub-segment (longest steady-velocity walk run; the airborne span; the projectile
  in-flight span) and calibrate on that, so small timing jitter does not invalidate a run or
  force re-authoring the window.
- A single **verdict table**: per constant → value, fit quality, status `PASS | REVIEW |
  RERUN(<experiment>)`; writes/merges `specs/calibration/gng_experiment_calibration.yaml`.

## Out of scope
- RAM↔CV cross-check (T20.6) — this orchestrator exposes a hook for it but does not implement it.
- Changing the experiment schema (T20.3) or the fit math (T20.4).

## Dependencies
T20.3, T20.4. (T20.6 plugs its cross-check into this orchestrator's verdict.)

## Reasoning grade
High — cross-subsystem orchestration (capture → vision → calibration), validation design that
must catch real failure modes without false alarms.

## Effort grade
Medium-High.

## Recommended model
Opus.

## Acceptance criteria
- One command produces the full calibration + a per-constant verdict table.
- Each experiment is validated immediately; a failure names the experiment, the failed check,
  and a concrete fix — no blind retry.
- Window auto-detection calibrates on the stable sub-segment; a small timing shift does not
  require re-authoring the window.
- Works both by launching scripted captures and by consuming existing run_ids (so it is usable
  without a live MAME when captures already exist).
- No new clean-room surface: output stays numbers-only; private paths never cross.
