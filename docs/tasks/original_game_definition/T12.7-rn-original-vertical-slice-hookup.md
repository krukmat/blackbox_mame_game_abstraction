# T12.7 — RN Original Vertical Slice Hookup

## Status

🔲 Planned

## Objective

Turn the RN prototype from a mechanics-playback engine into an original Signal Garden scenario prototype. The prototype must consume only public design artifacts (brief, encounter grammar, scene recipes, progression model, enriched asset recipes) and produce one playable vertical slice with placeholder or original-safe geometry.

## Why This Task Is Large

This task crosses the boundary from "engine that plays abstract data" (T11) to "engine that plays an original game." It requires:
- Loading and interpreting Signal Garden scene recipes in TypeScript
- Driving entity behavior from encounter grammar patterns (not hardcoded positions)
- Implementing at least one full scene from the T12.4 recipe set
- Mobile-appropriate touch input
- Placeholder rendering that reflects Signal Garden theme (not source visual identity)
- Ensuring the full app import graph contains no private paths or ROM-derived content

## Scope

- Implement `src/specs/sceneRecipeLoader.ts`: loads `specs/scenes/signal_garden_scene_recipes.yaml`, returns typed scene recipe
- Implement `src/specs/progressionLoader.ts`: loads `specs/progression/signal_garden_progression.yaml`, returns typed sequence
- Extend `SceneManager`:
  - `createSceneFromRecipe(recipe: SceneRecipe): SceneState` — positions entities according to recipe layout notes (not hardcoded coordinates)
  - `advanceProgression(sequence: Progression): SceneRecipe` — returns next recipe in progression
- Implement touch/keyboard input for: move left, move right, jump (fire optional for MVP)
- Implement one complete playable scene:
  - entities from recipe encounter pattern
  - calibrated physics from T11.3
  - collision and event detection working
  - scene ends on player death or progression condition
- Placeholder rendering: geometric shapes with Signal Garden palette from `DESIGN.md` — no sprites, screenshots, or source-derived visuals
- Verify full import graph has no reference to `evidence/private/`, ROM paths, or source media

## Out of Scope

- Production art or final assets
- App-store build
- Source-faithful stage reproduction
- Networking, save state, leaderboards
- T12.8 validation gate (separate task)

## Dependencies

- T12.4 (scene recipes must exist and be loaded)
- T12.5 (progression model must exist)
- T12.6 (asset recipes must exist — used to define placeholder shapes, not actual art)
- T11 complete (RN prototype must already load real mechanics and episodes)

## Effort

`L`

## Reasoning Grade

`High` — recipe-driven scene construction is new territory; encounter grammar → entity placement requires careful abstraction; touch input and rendering loop must work together deterministically; clean-room boundary must hold across a much larger TypeScript surface than T11

## Recommended Model

`Sonnet`

## Acceptance Criteria

- `src/specs/sceneRecipeLoader.ts` loads a real recipe file without error
- `createSceneFromRecipe` builds a valid `SceneState` from recipe data
- At least one complete Signal Garden scene is playable end-to-end (player can move, jump, encounter entities, scene can end)
- No hardcoded entity positions, encounter sequences, or visual identities remain
- Touch or keyboard input works for move and jump
- Placeholder rendering uses only Signal Garden palette and geometric shapes — no sprites
- Full TypeScript import graph contains no reference to `evidence/private/`, ROM paths, or source media
- All existing TypeScript tests pass plus new scene integration tests
- All Python tests pass (no regressions)
