# T12.4 — Scene Recipe and Transformation Rules

## Status

🔲 Planned

## Objective

Define how observed abstract patterns become newly authored Signal Garden scenes. Produce at least three clean-room scene recipes and the transformation policy that derives them from abstract mechanics.

## Scope

- Author `packages/schemas/scene_recipe.schema.json` — JSON Schema for scene recipe YAML
- Author `specs/transforms/mechanics_to_scene_rules.yaml`:
  - transformation rules that convert abstract mechanic inputs into scene parameters
  - required rules: scale normalization, role substitution, timing-band reuse, layout re-authoring, order variation
  - each rule must include a `no_copy` constraint: what may NOT be copied (coordinates, exact spawn sequence, source entity type names)
- Author `specs/scenes/signal_garden_scene_recipes.yaml` with ≥ 3 scene recipes:
  - Each recipe uses only encounter grammar roles as entity inputs (from T12.3)
  - Each recipe must specify:
    - `scene_id`: Signal Garden identifier (no source stage names)
    - `encounter_pattern`: reference to T12.3 grammar
    - `layout_notes`: abstract spatial description (left-to-right, vertical gap, etc.) — no pixel coordinates
    - `timing_source`: reference to T12.1 timing affordance, not source frame count
    - `divergence_note`: explicit statement of how this scene differs from source structure
    - `asset_roles`: list of abstract visual roles needed (not asset filenames)
- Verify schema validates all recipes
- Verify `ensure_no_private_paths` passes on all outputs

## Out of Scope

- Generating actual assets (T12.6)
- Progression sequencing (T12.5)
- Exact source level coordinates, enemy spawn timing, or stage structure

## Dependencies

- T12.3 (encounter grammar must exist — recipes reference grammar patterns)

## Effort

`M`

## Reasoning Grade

`High` — divergence notes are legally load-bearing; transformation rules must prevent coordinate copying; scene layout descriptions must be spatial abstractions, not pixel maps

## Recommended Model

`Sonnet`

## Acceptance Criteria

- `packages/schemas/scene_recipe.schema.json` validates `specs/scenes/signal_garden_scene_recipes.yaml` without errors
- ≥ 3 scene recipes exist, each citing abstract mechanic inputs only
- Each recipe has a non-empty `divergence_note`
- No recipe encodes source stage structure, source entity names, exact frame counts from private evidence, or pixel-coordinate layouts
- `mechanics_to_scene_rules.yaml` contains all five required transformation rule types
- `ensure_no_private_paths` passes on all three output files
