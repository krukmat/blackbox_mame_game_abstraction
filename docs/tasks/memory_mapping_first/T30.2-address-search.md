# T30.2 — Guided RAM address-search tool

## Objective

Provide a guided, in-emulator RAM address-discovery tool — the linchpin of the
memory-mapping-first architecture (ADR-028). Without it, "populate the memory map" is the
step that stalls. The tool finds entity/state addresses by the **observational**
RetroAchievements method (reset → filter by value change → narrow → verify by poke), never by
ROM disassembly (ADR-026 clause 1, ADR-028 clause 5).

The deliverable is two cooperating processes plus tests plus a **real verified artifact**:

1. A MAME Lua tap (`scripts/address_search.lua`) that dumps a full 64 KB RAM snapshot to a
   private exchange file every few frames, and reads a command file (pause/resume).
2. A Python TUI (`apps/mame-harness/address_search.py`) that reads snapshots, applies
   incremental filters over the candidate set, and saves accepted, named candidates to a
   private JSON.
3. Tests: the filter engine, snapshot reader, BCD detection, and a clean-room guardrail test
   proving the output JSON carries no private machine paths.
4. **A real guided-search session** producing verified `player_x` / `player_y` /
   `player_state` addresses for GNG, saved to
   `evidence/private/gng_address_candidates.json`.

## Why this is the linchpin

ADR-028 makes the memory tap the default position/state source. The tap (T30.4) can only read
addresses that this tool discovers. The whole re-architecture is blocked on producing a real
verified address set, which is the artifact this task delivers.

## Scope

- Harden the existing untracked draft (`address_search.py`, `address_search.lua`,
  `launch_address_search.sh`) into a correct, tested tool.
- Filter operators: `!=`, `<`, `>`, `= N`, `changed`, `unchanged`, with rolling baseline and
  undo.
- BCD vs `u8` encoding detection on accepted candidates.
- Verify-by-poke loop documented in the TUI help (address discovery is confirmed by observing
  the on-screen effect of the change — the value moves the way the variable should).
- Clean-room contract: addresses and raw values stay in private exchange files and the private
  candidates JSON only; nothing private is printed to stdout; the committed Lua/Python carry no
  real addresses.
- Tests for the filter engine, snapshot reader, BCD detection, and the no-private-path
  guardrail on the saved JSON.
- One real session producing verified GNG player addresses.

## Out of scope

- The declarative integration bundle schema (T30.3) and the tap wiring that consumes these
  addresses (T30.4).
- 16-bit / multi-byte variable search (u16 across two addresses). Single-byte `u8`/BCD only for
  the player-only slice; widen later if a constant needs it.
- Enemy / projectile address discovery (player-only first, per the plan's Out of Scope).
- Any public artifact change.

## Dependencies

- T30.1 ✅ (venv, MAME, ffmpeg, `cli.py doctor` green, `gng_controllable.sta` exists).
- The savestate anchor (`evidence/private/savestates/gng_controllable.sta`) so the search can
  start deterministically at the controllable state rather than re-booting each session.

## Design notes

- **Exchange protocol.** Lua writes `frame:u32_le || ram[0x10000]` to
  `<snapshot>.tmp` then atomically renames to `<snapshot>` so the reader never sees a partial
  file. Python polls for a new frame header before each filter.
- **Rolling baseline.** Each filter compares the current snapshot against the previous
  snapshot (not the original baseline), so "value increased since I last filtered" works for
  incremental narrowing. `baseline` command resets to the full 0x10000 candidate set.
- **Clean-room.** Snapshot/cmd/candidates files live under `evidence/private/` (gitignored).
  The committed scripts contain no real addresses (ADR-026 clause 1; ADR-028 clause 5).
