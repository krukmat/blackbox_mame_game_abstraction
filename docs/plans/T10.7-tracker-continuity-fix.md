# T10.7 — Tracker Continuity Fix (Plan)

## Status

Proposed — awaiting explicit approval before implementation.

## Objective

Eliminate the spurious `jump_start` clustering and bounding-box oscillation observed in the current `gng_trace.json` so that downstream physics calibration (T11.3) and episode extraction (T11.2) consume a self-consistent signal.

Concretely: of 174 `jump_start` events in the current trace, ≥ 130 are detector artifacts (duration=1 frame, identical-height re-detections, oscillating bounding boxes). The current calibration derives `jumpVelocity = 0.033478/frame` and `gravity = 0.092343/frame²`, which together imply `t_peak ≈ 0.36 frames` — physically inconsistent with the observed mean arc duration of ~16 frames in the few clean samples. This blocks any T11.4 work that depends on game-feel fidelity, and it leaks downstream into T12 scene design.

## Why Now

- **T11.4 is blocked on calibration quality**: the parent handoff (`docs/handoff_t11_3_physics_calibration.md`) explicitly flags this as a risk that "will need revision" before T12.
- **Re-extraction is cheap**: `vision_pipeline.extract_run_trace` operates over the already-captured PNG frames in `evidence/private/run_t10_4_01/frames/`. No new MAME run is required.
- **Tracker fix is local**: the changes are confined to `packages/vision/arthur_tracker.py` and `packages/vision/trace_extractor.py`. No public artifact schema changes; no ADR-001/003/006 boundary changes.
- **The alternative paths fail**: manual calibration from public docs would change the calibration *source* (away from "measured from trace"), and continuing T11.4 with bad numbers requires costly rework at T12.

## Root Cause Analysis

Three coupled defects in the vision layer:

### Defect 1 — No velocity ceiling in `ArthurTracker.find_arthur`

[arthur_tracker.py:22-47](packages/vision/arthur_tracker.py#L22-L47) selects candidate regions by height, center_y, and aspect ratio. When multiple regions qualify it picks the nearest to `prev_center`. There is no upper bound on how far that "nearest" candidate may be from `prev_center`.

Consequence: when Arthur is briefly undetected (crouch, fire animation, sprite swap) and a different blob in the signature range appears far from his last position, the tracker accepts it. This produces a teleport in the trace and a fake `velocity_y` spike.

### Defect 2 — No `jump_start` debounce in `_infer_events`

[trace_extractor.py:151-153](packages/vision/trace_extractor.py#L151-L153) emits `jump_start` on any `_PRE_JUMP_STATES → ascending` transition. A single noisy frame where the bounding box edge fluctuates upward triggers the event, even if Arthur was just briefly idle for one frame after a previous jump.

Consequence: a real jump arc that has a brief detection gap mid-flight (very common — Arthur's crouch/death/fire animations break the signature) gets segmented into 2–3 fake jumps.

### Defect 3 — Single-frame Δposition for velocity

[trace_extractor.py:61-72](packages/vision/trace_extractor.py#L61-L72) computes `vy = (curr.center_y - prev.center_y) / frame_height` between consecutive frames only. Bounding-box edge noise of 2–4 px between adjacent frames produces |vy| ≈ 0.01–0.02 normalized, well above the `VY_STILL = 0.005` threshold.

Consequence: many "idle" Arthur frames get classified as `ascending` or `descending`, generating false events that contaminate the calibrator sample set.

## Design Decisions

### Decision 1 — Add `max_frame_jump_px` to `ArthurSignature`

A new field that rejects candidate regions whose distance from `prev_center` exceeds the empirically validated upper bound for one frame of motion. Default value: **24 px** (empirically derived — see "Empirical Calibration" section below).

When all candidates are rejected, `find_arthur` returns `None` — the existing `player_gap_tolerance` mechanism (T10.6-E) already handles gaps gracefully.

**Why not just lower the signature ranges?** The ranges encode shape, not motion. Tightening them breaks legitimate detection during ascending frames (which the existing code already expanded for). The right invariant is velocity-based, not geometric.

#### Empirical Calibration — distribution of |Δy| between consecutive player frames

Measured from current `specs/traces/gng_trace.json` (1144 consecutive-frame samples):

| Range (px) | Count | % | Interpretation |
|------------|-------|----|----------------|
| [0, 1) | 490 | 42.83% | Idle stillness |
| [1, 12) | 219 | 19.16% | Real motion (walking, descending, jumping) |
| [12, 24) | 64 | 5.60% | Borderline — real fast falls + bbox flicker |
| [24, 30) | 32 | 2.80% | Mostly bug |
| [30, 50) | 108 | 9.44% | Clear teleport bug |
| [50, 110) | 176 | 15.38% | Severe cluster artifacts |
| [110, 200) | 41 | 3.58% | Off-screen anomalies |

The distribution is clearly bimodal — a clean motion cluster below 12 px and a bug cluster above 30 px. The "valley" between them is the right place to set the threshold:

- **24 px** rejects 30.77% of consecutive-frame pairs — captures all bimodal-bug samples while preserving observed maximum real motion (~14 px/frame at frame 2073→2074 — a confirmed `jump_start` event)
- Threshold of 12 would reject 38.02% — too tight, would lose legitimate fast falls (e.g., frames 2090-2091: `idle → descending` with `fall` event, |Δy|=14.45 px)
- Threshold of 48+ would still admit the 30-50 px cluster which is mostly bug artifacts

The 70% safety margin between the chosen threshold (24) and observed max real motion (14) accounts for unmeasured edge cases (high-platform falls, knockback animations).

### Decision 2 — Add ground-streak debounce in `_infer_events`

Require ≥ `MIN_GROUND_STREAK = 3` consecutive grounded frames before allowing a new `jump_start`. Pass a `ground_streak: int` counter through the per-entity state.

**Why 3 and not higher?** GNG's minimum landed-then-jump-again cadence is observed at ~3 frames (50 ms at 60 fps) — anything stricter rejects legitimate quick re-jumps. Anything lower (1, 2) preserves the current noise.

**Why not just filter the calibrator output?** Same problem next time. The trace itself should be the canonical artifact; filtering at consumer level pushes the burden downstream and breaks ADR-008 reproducibility (every consumer would re-filter).

### Decision 3 — Optional median-window position smoothing (deferred)

Median-of-3 position smoothing would further reduce velocity noise. **Deferred** because:
- It changes the trace's spatial accuracy contract (frames now reflect smoothed positions, not raw detections)
- It would require ADR amendment
- The first two fixes are expected to eliminate the clustering on their own — measure first, optimize if needed

If validation after Decisions 1+2 still shows residual noise, this becomes T10.7.1 or T10.8.

### Decision 4 — Re-extract trace, regenerate downstream artifacts

After tracker changes pass tests:
1. Re-run `vision_pipeline.extract_run_trace` on `run_t10_4_01`
2. Replace `specs/traces/gng_trace.json`
3. Re-run `physics_calibrator` → new `specs/calibration/gng_physics_calibration.yaml`
4. Re-run `episode_extractor` → new `specs/episodes/gng_episodes.json`
5. Update `specs/mechanics/gng_abstract_mechanics.yaml` calibrated values
6. Update `PhysicsSystem.ts` `CALIBRATED_PHYSICS_CONFIG`

### Decision 5 — Validation gate before T11.4 unblock

T10.7 is complete only when:
- `gng_trace.json` has `< 30` `jump_start` events (was 174) — clustering eliminated
- Back-calculation `t_peak = v0/g` matches observed `t_peak` within ±30%
- All existing vision/harness tests pass

If the cleaned trace fails the back-calc consistency gate, T10.7 is **not complete** even if the code changes are merged — a follow-up sub-task is required.

## Out of Scope

- Generic multi-game player tracker abstraction (ADR-012 explicitly defers this)
- MOG2 scroll reset (ADR-013 Known Gap, tracked separately for T12)
- Median-window position smoothing (deferred — Decision 3 above)
- Multi-entity tracking continuity for enemies (different problem)
- New evidence capture run (the existing `run_t10_4_01` frames are sufficient)
- Changing the trace JSON schema

## Risks

- **R1 — `max_frame_jump_px=24` may reject high-platform falls**: Resolved by empirical calibration — observed max real motion is ~14 px/frame with 70% safety margin. If a legitimate fall exceeds 24 px (e.g., dying off-screen), it would be rejected, but `player_gap_tolerance` bridges short gaps gracefully.
- **R2 — `MIN_GROUND_STREAK = 3` may reject legitimate quick taps**: GNG allows very rapid jump inputs. Mitigation: validate against any frames where input plan shows back-to-back `jump` actions <3 frames apart.
- **R3 — Calibrated values shift significantly**: RN prototype tests may break on the new values. Mitigation: tests assert "not equal to hardcoded stubs", not specific values; should still pass.
- **R4 — Episode boundaries shift in regenerated `gng_episodes.json`**: T11.2 acceptance criteria require ≥3 episodes with ≥1 jump each. With cleaner trace, jump_start counts drop — verify episodes still qualify.

## Reasoning Grade

`High` — cross-module impact (vision → trace → calibration → RN), clean-room boundary preserved (changes are numeric-only), but the empirical validation step (back-calc consistency check) introduces uncertainty about completion criteria.

## Effort Grade

`M` — five subtasks, mostly mechanical once design is fixed, but TDD coverage requires careful synthetic test fixtures, and the regeneration pipeline must be exercised end-to-end.
