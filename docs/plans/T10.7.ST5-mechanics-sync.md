# T10.7 ST5 — Mechanics YAML Sync + Episode Regeneration

## Objective

Eliminate the remaining numeric drift between
`specs/calibration/gng_physics_calibration.yaml` (canonical calibrated values)
and `specs/mechanics/gng_abstract_mechanics.yaml` (public mechanics surface),
then regenerate `specs/episodes/gng_episodes.json` from the current trace and
verify the T11.2 acceptance gate still holds.

This closes T10.7 as a unit. The four physics constants
(`locomotion_velocity_x`, `jump_velocity_y`, `gravity_units_per_frame`,
`projectile_velocity_x`) become structurally consistent across the public
calibration → mechanics → RN consumption chain.

## Scope

- Update `mechanics.jump_arc.fields.velocity_y` calibrated values to match the
  calibration YAML (`0.007825 / 0.4668`, n=2, source_method
  `human_validated_kinematic`).
- Update `mechanics.gravity_collision.fields.gravity_units_per_frame`
  calibrated values to match the calibration YAML (`0.001956 / 0.1167`, n=2,
  source_method `human_validated_kinematic`).
- Remove the stale `note: "trace sign inverted vs PhysicsSystem; jumpVelocity
  = |measured| = 1.9966"` since the value is now the absolute calibrated form.
- Refresh the mechanics YAML header comment to drop the lingering T11.3
  attribution that no longer applies after T10.7.A/C/E re-derived all four
  constants from human-validated picker candidates.
- Run `apps/mame-harness/episode_extractor.py` against the current trace
  (regenerated from `run_t10_7_proj2` during T10.7.E) and replace
  `specs/episodes/gng_episodes.json`.
- Verify the T11.2 acceptance gate: at least 3 episodes, each containing at
  least one `jump_start` event for the player entity.

## Out of Scope

- Modifying `apps/rn-prototype/src/engine/PhysicsSystem.ts`. The
  `CALIBRATED_PHYSICS_CONFIG` constants already match the calibration YAML
  (gravity=0.1167, moveSpeed=0.2786, jumpVelocity=0.4668). No `projectile`
  field is added to `PhysicsConfig` because the engine does not yet simulate
  projectiles; introducing an unused constant would violate the project
  guidance against speculative abstractions.
- Modifying `apps/rn-prototype/tests/engine.test.ts`. The current assertions
  only reject the pre-calibration stubs (9.8 / 3 / 6); the synced values still
  pass these gates without threshold changes.
- ADR-013 / Obsidian / CLAUDE.md / AGENTS.md Known Gaps updates. Documentation
  refresh is ST6 work.
- Full Python + RN test suite run. That is ST7 work.
- Any change to the picker tools, calibrator, or trace extractor.

## Design Decisions

### D1 — No new fields in `PhysicsConfig`

PhysicsSystem.ts owns gravity, moveSpeed, and jumpVelocity because step()
applies all three each frame. Projectile motion is not simulated by the
engine today; it will be introduced as a separate ProjectileSystem when
T11.4 needs it. Adding `projectileVelocity` to `PhysicsConfig` now would
ship a dead constant whose only consumer is the test file. Defer the
addition until a real consumer exists.

### D2 — Episode regeneration consumes the proj2 trace, not a jump-focused trace

`specs/traces/gng_trace.json` was last regenerated during T10.7.E from
`run_t10_7_proj2`. That trace contains 175 `jump_start` events and 17 `land`
events (per the extraction summary). The T11.2 acceptance gate is "≥3
episodes with ≥1 jump_start each" — that threshold is comfortably reachable
from this trace. If the gate fails empirically, the failure surfaces a
deeper issue (extractor logic, trace quality) and ST5 must not patch around
it; it must be raised as a new finding before completion.

### D3 — No assertion-threshold changes in `engine.test.ts`

The three engine tests only guard against the pre-calibration stub values
(gravity=9.8, moveSpeed=3, jumpVelocity=6). The synced values
(0.1167 / 0.2786 / 0.4668) are not equal to any stub, so the tests pass
without modification. Editing them now would be a no-op churn.

## Module Dependencies

- `episode_extractor.py` reads `specs/traces/gng_trace.json` and writes
  `specs/episodes/gng_episodes.json`. Both paths go through
  `guardrails.ensure_public_output_path` / `ensure_no_private_paths`.
- `mechanics YAML` is consumed by `apps/rn-prototype/src/specs/mechanicsLoader.ts`
  via `loadAbstractMechanics`. The loader reads `timing` and the calibrated
  values but does not enforce inter-YAML consistency — that is exactly the
  gap ST5 closes manually.

## Validation Gates

1. `specs/mechanics/gng_abstract_mechanics.yaml` and
   `specs/calibration/gng_physics_calibration.yaml` agree on all four
   constants (value_per_frame, value_per_second, sample_count, source_method).
2. `specs/episodes/gng_episodes.json` contains ≥3 episodes; each episode has
   ≥1 frame whose player events include `jump_start`.
3. No file under `evidence/private/` is referenced as a path in any updated
   public artifact (guardrails layer enforces this on write).

## Risks

- **R1**: Episode regeneration may yield fewer than 3 qualifying episodes if
  the trace's `jump_start` events cluster in time. Mitigation: surface the
  failure rather than patch the gate; relax `GAP_THRESHOLD` only with
  documented justification.
- **R2**: A future contributor may re-introduce drift by editing one YAML and
  not the other. Mitigation is out of scope here; ADR or test-time
  consistency check could be filed as a separate gap.
