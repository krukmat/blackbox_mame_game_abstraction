# T10.8 — Enemy Tracking Continuity (Plan)

## Status

Proposed — awaiting explicit approval before implementation.

## Objective

Provide cross-frame identity continuity for non-player entities (enemies) in GNG stage 1 screen 1, so that `specs/traces/gng_trace.json` exposes a coherent per-enemy lifecycle (`spawn → motion → die`) instead of the current ephemeral frame-indexed IDs (`enemy_a_{frame}_{region_index}`).

This unblocks downstream consumers — `T11.2` episode extractor, `T12` encounter grammar — by producing trace records where the same physical enemy keeps the same `entity_id` across all frames in which it appears.

Scope is explicitly limited to **screen 1 of stage 1 without camera scroll**. Boss encounters (Red Arremer, cyclops) are deferred to a follow-up T10.9.

## Why Now

- **ADR-013 Known Gap**: "Cross-frame enemy ID continuity is not implemented — enemies remain ephemeral per-frame entities." Documented as a deferred limitation since T10.6.
- **Blocks T11.2 quality**: `episode_extractor.py` groups frames by player presence and enriches with enemy data. Without enemy identity continuity, every episode treats every detected enemy region as a brand-new entity, which destroys any per-enemy locomotion measurement and inflates spurious `spawn` events.
- **Blocks T12 design integrity**: `T12.3` encounter grammar and `T12.5` progression require enemy archetypes with measured movement constants. Those constants cannot be derived from a trace that does not preserve enemy identity.
- **Re-extraction is cheap**: The fix lives entirely in `packages/vision/`. No new MAME capture is strictly required for screen 1 — existing `run_t10_4_01` frames already contain zombi and crow appearances. A short complementary capture may be added for signature calibration if the existing evidence is sparse for one enemy type.

## Root Cause Analysis

Two coupled defects in the vision layer cause the absence of enemy continuity:

### Defect 1 — Frame-indexed entity IDs

[trace_extractor.py:222-229](packages/vision/trace_extractor.py#L222-L229) generates non-player entity IDs as `f"{entity_type}_{frame}_{region_index}"`. The frame number is part of the ID, so a zombie detected in frame 1500 (`enemy_a_1500_0`) and in frame 1501 (`enemy_a_1501_0`) are treated as two separate entities.

**Consequence:** Every frame in which an enemy is detected fires a `spawn` event (ADR-012 Rule 6 logic at trace_extractor.py:385-388), because the per-frame ID is always new. The trace contains hundreds of spurious `spawn` events and zero meaningful `die` events for enemies.

### Defect 2 — No tracker for non-player entities

[arthur_tracker.py:23-58](packages/vision/arthur_tracker.py#L23-L58) provides `ArthurTracker.find_arthur` which encodes nearest-neighbor matching with a velocity ceiling — but the matcher is single-target and signature-locked to Arthur's geometric range. There is no equivalent for enemies, so even if the IDs were stabilized, there is no logic to decide *which* enemy in frame N is the same as *which* enemy in frame N+1 when multiple are on screen.

**Consequence:** Even with persistent IDs, the matching problem is unsolved. A naive sorted-order assignment is incorrect when enemies cross paths or one despawns mid-frame.

## Design Decisions

### Decision 1 — Generalize `ArthurTracker` into a reusable `EntityTracker`

Extract a base class capable of tracking multiple entities of multiple types simultaneously, keyed by signature.

```python
@dataclass(slots=True)
class EntitySignature:
    entity_type: str                   # "enemy_a", "enemy_b", "projectile", ...
    height_min_px: int
    height_max_px: int
    center_y_min_px: int
    center_y_max_px: int
    aspect_ratio_min: float
    aspect_ratio_max: float
    max_frame_jump_px: float           # per-type velocity ceiling
    gap_tolerance_frames: int = 0      # per-type gap tolerance (mirrors player_gap_tolerance)

class EntityTracker:
    def __init__(self, signatures: list[EntitySignature]) -> None: ...
    def step(self, regions: list[MotionBox], frame: int) -> list[TrackedEntity]: ...
```

The tracker maintains a per-type track table that survives across frames. Each track has a stable `entity_id`, a `last_seen_frame`, a `last_position`, and a `signature_type`. On each frame:

1. Filter incoming `regions` by signature bounds (height, center_y, aspect_ratio) per type.
2. Greedy nearest-neighbor assignment between active tracks and matching candidates, respecting `max_frame_jump_px` per type.
3. Unmatched candidates become new tracks (allocate a fresh `entity_id`).
4. Unmatched active tracks increment a missing-frame counter; once `gap_tolerance_frames` is exceeded, the track is closed (emit `die` retroactively on its last-seen entry).

`ArthurTracker` becomes a thin wrapper over `EntityTracker` with a single `EntitySignature` for the player. Existing behavior is preserved.

**Why a single tracker for all entities and not per-type instances?** A single tracker can disambiguate cases where a candidate region falls into the intersection of two signature bounds (e.g., a small enemy and a large projectile that overlap in height). Greedy assignment with global view avoids double-counting.

### Decision 2 — Persistent `entity_id` scheme

Replace `{entity_type}_{frame}_{region_index}` with `{entity_type}_{spawn_frame}_{spawn_index}`. The frame in the ID is the **spawn frame**, captured once and immutable for the life of the track.

`spawn_index` disambiguates multiple entities spawned in the same frame (e.g., two zombies emerge simultaneously). It is allocated by the tracker, not by the per-frame region order.

**Why include the spawn frame in the ID at all?** Stability: spawn frame is invariant; alternatives (UUIDs) are opaque to humans inspecting the trace; alternatives (monotonic counters) are not reproducible across re-extractions.

### Decision 3 — Signatures calibrated via human-validated picker (ADR-019)

`EntitySignature` bounds for each enemy type are calibrated using the same picker pattern established in `T10.7.A` (`apps/mame-harness/visual_jump_picker.py`) and `T10.7.C` (`apps/mame-harness/walk_segment_picker.py`).

A new `apps/mame-harness/enemy_signature_picker.py` surfaces candidate enemy regions from `run_t10_4_01` (and optionally a short complementary capture) grouped by sustained area+aspect_ratio cluster. The operator validates each candidate by inspecting the private PNGs and accepts/rejects them. Accepted candidates feed `enemy_signature_calibrator.py` which computes the per-type bounds.

This keeps the bounds reproducible, traceable to specific private frames, and free from speculative tuning.

### Decision 4 — Scope: screen 1, two enemy types

Stage 1 screen 1 (no camera scroll) contains:

- **Zombi**: rises from the ground at fixed spawn points, walks horizontally toward the player. Stationary periods in the grave before emerging. Most common enemy.
- **Cuervo / raven**: enters flying with vertical oscillation. Smaller, higher in the frame.

Out of scope for T10.8:

- **Red Arremer** (devil): jumps and flies erratically; appears later in stage 1. Deferred to T10.9.
- **Stage 1 boss** (cyclops / "Big Men"): appears after camera scroll, which itself requires the ADR-013 MOG2 scroll reset gap to be resolved first. Deferred to T10.9.
- **Static hazards** (graveyard plants/cactus): not entities, no continuity needed; current `_entity_type_from_box` `hazard` classification stays as is.
- **Enemy projectiles** (thrown lances): deferred — projectile tracking belongs to T10.7.E surface area.

### Decision 5 — Regenerate trace + validate against quality gates

After implementation, regenerate `specs/traces/gng_trace.json` from `run_t10_4_01` and verify:

- Per-enemy track duration ≥ 5 frames for ≥ 80% of tracks (no flicker-only false tracks).
- `spawn` event count per enemy type ≤ 30 in the full run (was unbounded — each frame contributed one).
- Every track that spawns has either a `die` event or terminates at the last frame of the run.
- No track exceeds the run length in `last_seen_frame - spawn_frame + 1`.

These are sanity gates, not absolute physical truth — passing them indicates the tracker is producing coherent output, not that every enemy classification is correct.

## Empirical Calibration Plan

Bounds for `EnemySignature` per type will be derived as follows:

1. **Pre-survey**: Run a one-shot script over `run_t10_4_01` PNG frames to extract `MotionBox` clusters by area+aspect_ratio, dump to a private CSV under `evidence/private/run_t10_4_01/logs/enemy_pre_survey.csv`. Numeric data only.
2. **Picker pass**: `enemy_signature_picker.py` groups CSV rows into candidate clusters and presents frame ranges to the operator for validation against private PNGs (e.g., "frames 1820-1845, height 28-32 px, center_y 178-186 px — accept as zombi? y/n").
3. **Calibration**: `enemy_signature_calibrator.py` consumes the accepted clusters and computes the bounds with a margin (e.g., min/max ± 2 px for height, ± 0.05 for aspect_ratio). Output: `specs/calibration/gng_enemy_signatures.yaml` (public, numeric only).

If `run_t10_4_01` lacks sufficient samples for either type (< 5 accepted clusters), a short complementary capture is performed under `run_t10_8_enemies` with the user driving Arthur into known enemy spawn points.

## Risks

- **R1 — Zombi partial occlusion by player**: When Arthur attacks a zombi, the player and enemy overlap. The `FrameDiffer` may return a single merged region, breaking both player and enemy tracking for one or more frames. *Mitigation*: existing `player_gap_tolerance` already bridges player gaps; enemy `gap_tolerance_frames` defaulted to 3 covers the same case.
- **R2 — Crow signature overlaps with projectile signature**: A flying crow at small height/aspect_ratio can collide with the `_RATIO_PROJECTILE` bound in `_entity_type_from_box`. *Mitigation*: signatures take precedence over area-ratio fallback; `_entity_type_from_box` is consulted only for regions unclaimed by any signature.
- **R3 — MOG2 misses stationary zombis**: A zombi waiting in the grave for several seconds may be absorbed into the background model. *Mitigation*: zombis only matter once they begin emerging; emergence introduces motion that breaks the static absorption. Calibrated `mog2_history` (300) should be sufficient.
- **R4 — Greedy assignment errors when enemies cross paths**: Two zombis walking past each other can swap IDs under naive greedy nearest-neighbor. *Mitigation*: the `max_frame_jump_px` ceiling prevents long-distance reassignments; for screen 1, enemies typically do not cross paths within the velocity ceiling window. Hungarian assignment is deferred unless validation gates fail.
- **R5 — Tracker refactor breaks existing ArthurTracker tests**: The base class change must preserve all current `ArthurSignature`/`ArthurTracker` behavior. *Mitigation*: keep `ArthurTracker` as a thin wrapper; existing tests must pass unchanged.

## Dependency Order

T10.8 inserts after T10.7.E (Projectile In-Flight Tracking) and before T11.2 (Trace Episode Extractor).

Rationale:

- T10.7.E establishes the cross-frame continuity pattern for a single entity type (projectile). T10.8 generalizes the same idea to multiple concurrent entities of multiple types. The `EntityTracker` refactor in T10.8.2 should subsume the projectile tracking work where structurally compatible.
- T11.2 episode extraction consumes whatever the trace says; if enemies have no continuity, episodes are degraded. T11.2 must run on a trace with enemy continuity to be worth the effort.

## Exit Criteria

T10.8 is complete when all of the following are true:

1. `EntityTracker` exists, has signature-driven matching, and `ArthurTracker` is a thin wrapper preserving all existing behavior.
2. `gng_enemy_signatures.yaml` exists, calibrated from human-validated picker output.
3. `trace_extractor.extract_trace` produces non-player IDs of the form `{entity_type}_{spawn_frame}_{spawn_index}`, persistent across frames.
4. Regenerated `gng_trace.json` passes the validation gates in Decision 5.
5. ADR-021 exists; ADR-013 Known Gap "Cross-frame enemy ID continuity" is removed.
6. All existing Python + TypeScript tests pass with no regressions.
7. New regression tests for the tracker and enemy lifecycle pass.
